## 实装

1. 长按仍先走 102 组同步。严格 await 视频账本，读失败不能当作空账本；有未送达视频时持久化当前训练日、原长按时间与等待状态，显示既有奖励页但不请求完成接口。
2. 新 `VideoCompletionPresentation` 只产生当天计数与显示态，失败分类复用 A `VideoDeliveryPresentation.hasFailure`。C 汇总与小字接原长按控件；D 替换该位置，使用金色进度条，等待中仍可编辑记录。奖励页关闭调用 A `retryFailures`，保留缺文件补选入口。
3. `VideoCompletionCoordinator` 持续读取当前账本和当前组队列；新增/替换视频、等待中改组记录都会重新参与条件。全部就绪才通过既有闸门请求完成，回写现有计划/已完成态，并发完成通知。
4. 完成等待和超时标记沿用现有 completion 持久存储。完成回执先落盘，通知调用完成后才清意图；重启可恢复尚未完成的通知工作。长按返回奖励页之前即安排系统 30 分钟通知，因此不依赖前台计时器存活。全部视频送达后取消尚未触发的超时请求。
5. 三类通知复用 A 的单一聚合 ID 和点击路由。通知写入经 `UploadNotificationDeliveryQueue` 串行化，较早失败通知跨 await 后不能覆盖较新完成通知；超时只发一次，拒绝通知权限不阻止完成。
6. `VideoUploadServices.backend` 在 App 依赖组装时注册完成恢复 hook，先等待认证 bootstrap，再消费后台事件。`StudentSetSyncRuntime` 按当前账号恢复一个队列，`StudentSetSyncHost` 复用同一实例。恢复不依赖 View 出现；账号变化或无有效账号时不恢复旧账号意图。
7. `Session.bootstrap` 增加 single-flight 等待，防止后台入口在前台正在认证时立即返回。背景 pipeline 与 `BackgroundEventDrain` 在 OS token ack 前 await 完成/通知恢复。
8. manager 在 `enqueue` / `retainForSet` 首个 await 前登记当天在途选择，严格快照包括未落账本的选择；替换时旧视频仍为 uploaded 也不能提前释放闸门。快照遇选择版本变化会重新读取。
9. 中英新增文案按卡，繁体通过现有 `generate-zh-hant.py --keys …` 生成。既有已完成日不会凭视频状态创建等待意图；无视频/全部已送达仍走原完成路径。

## 真机走查返修（2026-11-05，Opus 接手，Codex 额度不足降级为 Claude 实装）

David iPhone 12 走查两处问题，均先写回归测试（修前红、修后绿）：

1. **断网拍的视频联网后已送达，但每组录入页都显示「视频处理失败,请重试」**。根因：拿不到组 id（断网、组还在排队）是正常的挂起路径，却调用了 `reportVideoProcessingFailure()`；而这条提示是全局一条，所有组的录入页都显示，挂起绑定成功时也可能清不掉。修：挂起路径不再报错；绑定被新选择取代（CancellationError）不报错；失败提示记录所属的 draft，录入页只显示本组或不属于任何组的提示。测试 `pendingVideoIsNotAProcessingFailureAndFailuresStayOnTheirSet`。
2. **飞行模式下长按完成，奖励页弹出后立刻被撤下**。根因：当天视频已全部送达、组已同步，`deferIfNeeded` 不等待，直接调完成接口；断网请求失败走旧分支，`completionPhase = nil` 撤掉奖励并回退。修（David 拍 A）：完成请求因连接失败（`URLError` / `NSURLErrorDomain`）失败时，把当天挂进同一个完成闸门的等待（0 条视频），奖励页保留，训练页底部显示「等待联网完成今日训练 / 联网后会自动完成…」，联网后由协调器每 2 秒的刷新补发完成并发「今日训练已完成」通知（0 条视频时不带条数）。业务拒绝（`PlanDayCompletionError`）保持原行为。测试 `offlineCompletionKeepsRewardAndCompletesWhenOnline`、`waitingCardWithoutVideosSaysItWaitsForConnection`。
