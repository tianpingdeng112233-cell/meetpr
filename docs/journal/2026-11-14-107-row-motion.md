# 107 · 全天一览动作标题滑动（T1 / P1）

基线 release/1.0 @ 93261af5。点第二个动作时，第一个动作的组表收起，第二行边框先就位，标题与摘要还从下方滑进。预期是行高和文字同帧就位。范围仅 iOS 全天一览的展开、收起、切换；手动滚动、按压样式、组编辑、完成逻辑均沿用现状。main 没有这个视图。

在 iPhone 17e / iOS 26.5，MeetPR-DemoStudent 用 `-student-empty-state pct-anchors -AppleLanguages (zh-Hans) -AppleLocale zh_CN -meetpr.appearance light` 启动，停在页顶，先展开「竞技深蹲」，再点下一行「传统硬拉」。保存整段切换录屏，将同一标题在切换前后的位置作为两个候选框。除了换行的那一帧，标题应始终完整留在其中一个框内；不能先消失、出现在中间或来回闪动。用户录屏也在相同交互的第 122–126 帧检出标题经过中途位置。

单改标题按钮的按压样式未消除位移，已撤回。对照实验中，仅在展开动作 ID 改变时让整张表立即重排（清空 SwiftUI transaction 的 animation，并阻止子视图重新加入隐式动画），就能消除位移。判据不依赖具体动画 API。没有修改滚动位置或训练数据；在线训练和只读预览共用该视图。
