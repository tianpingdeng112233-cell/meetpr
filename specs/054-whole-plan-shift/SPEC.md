# spec 054 — 学员单日顺延 V2:整体计划后移(取代 V1"挪到休息日")

状态:Approved(David 2026-07-11 四拍板,见 §拍板记录)。V1(#234b 落线未发布)原地演进,用户永远只见 V2 语义。

## 语义(一句话)

学员在训练日点「今天有事」→ **从今天起的所有剩余课程整体后移一天**(今天的课变明天,
之后依次顺延,周期结束日 +1);已完成的过去日不动;可跨日叠加;可撤销最近一次(仅当天)。

为什么换:课与课的顺序/间隔是编排的一部分(恢复间隔、连续日压力),V1 把今天的课单独塞进
本周休息日会破坏序列;V2 序列原封、时间轴整体滑一格,与 `day_of_week=位置式` 正典同构。
V1 死穴(本周无休息日→无法顺延)在 V2 不存在。

## 拍板记录(2026-07-11)

1. **叠加无硬上限**;累计 ≥3 天时 iOS 弹提示「建议联系教练调整计划」。
2. **撤销 = 只撤最近一次 batch,且仅创建当天(UTC)内**——即刻反悔归学员,跨天调整归教练。
3. **跨周期碰撞**(顺延后周期尾与下个已发布周期重叠):先允许 + 教练端可见,遇见再定规则。
4. **V1 处置**:原地演进,1.0(9) 切包前完成替换;计划树不可变哲学不变。

## 数据模型(复用 V1 覆盖表,迁移 0038)

- `plan_day_shifts` 增列:`batch_id uuid NOT NULL`(V1 存量行如有,回填独立 uuid)、
  确保有 `created_at`。表仍是覆盖层,**不改教练计划树**。
- 一次顺延动作 = 一个 batch:对「今天(UTC)起所有剩余 plan day」各写一行,
  `shifted_to_date = 当前生效日期 + 1 天`(叠加时基于上一 batch 的生效日再 +1)。
- 撤销 = 删除最新 batch 全部行。
- 每日生效日期 = 原日期被最新覆盖行取代(GET 序列化机制与 V1 完全一致,**不变**)。

## API(替换 V1 的 day 级端点;V1 端点无线上调用方,直接移除)

- `POST /plans/:planId/shift` → 201 `{ batch_id, shifted_days: [{day_id, shifted_to_date}], total_offset_days }`
  - 门:请求者为该计划的 coached 学员;UTC 今天是该计划的训练日(生效日期口径);
    今天的课无任何 set log;(碰撞不阻止,per 拍板 3)
  - 错误码(沿用 V1 中文映射风格):`SHIFT_ONLY_TODAY` / `ALREADY_STARTED` / `NOT_PLAN_STUDENT` / `PLAN_NOT_ACTIVE`
- `DELETE /plans/:planId/shift` → 204(撤最新 batch)
  - 门:存在 batch;最新 batch 创建于 UTC 今天;被撤回到今天的课未开始
  - 错误码:`NO_ACTIVE_SHIFT` / `UNDO_WINDOW_PASSED` / `ALREADY_STARTED`
- GET 计划序列化:不变(逐日 `shifted_to_date`),另加计划级 `total_shift_days`(Σ batch,供教练徽标)。

## iOS 行为

- 入口五门不变(coached/今天/未开练/UTC 凌晨门/…);V1"找休息日"逻辑删除。
- 确认弹窗:「把整份计划往后顺延一天?今天的◯◯课改到明天,之后的课依次顺延,
  本周期结束日变为 X月X日」;确认调 POST。
- 顺延后:今日卡休息态 + 红字「撤销顺延」(仅当最新 batch 为 UTC 今天创建时显示);
  撤销二次确认文案不变。
- 累计 ≥3 天(total_shift_days ≥ 3):顺延成功后追加提示「已累计顺延 N 天,建议联系教练调整计划」。
- 教练端:逐日"已顺延"标记**替换为**计划级徽标「已顺延 N 天」(执行页头部);
  周概览/分诊照常跟生效日期走。
- Demo(InMemory)按同语义实现;种子保持 UTC 午夜锚(已修)。

## 不做 / 边界

- 不跨计划、不动 start_date、不动过去日;休息日无入口;solo 无此功能(冻结)。
- 碰撞检测/提示:本版不做(拍板 3)。
