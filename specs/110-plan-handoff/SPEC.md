# 110 — 旧周期练完再接新计划

- **状态**：Draft。核心规则已确认；下述入口布局与存量首次选择方案待 David 看稿。
- **来源**：2026-11-16 教练 / 学员反馈及截图；David 最后一条明确决定：**“旧计划练完自动接新计划，同时保留主动提前切换入口”**。它取代同一会话较早的“保留发布即切换”选项。
- **分级**：T2 / P1。本稿不代表已实装、已纳入 iOS 42 或已发布。
- **正典范围**：本文件管理跨周期接续规则；单计划内训练、记录、视频与撤销继续遵守 107 / 101 / 102 / 104。实施时同步 backend 035 与两端消费者，不沿用 071 的“新计划发布即翻篇”。

## 问题与已核实事实

反馈截图：教练仍可打开 10/19 开始、共 5 周的计划，W5 是 11/16 周；另一份 11/23 开始的计划已发布。学员端显示了新计划的 W1、11/24 训练日。

iOS 41（`84bd30b0`）的 `BackendStudentPlanRepository.refreshCurrentPlanFromBackend` 从已发布列表取 `max(by: planPrecedes)`；比较器只比较 `publishedAt / createdAt / id`，不检查旧计划完成情况或新计划开始日期。071 与 backend 035 都明确约定过“发布即翻篇”。

backend `42194b1` 对应源码中，发布操作更新目标计划自身；按 ID 读取与训练日完成接口按归属和 published 状态校验，不要求是最后发布的计划。此处是代码核查，尚未读取受影响账号数据库，不能据此宣称已验证该账号全部历史数据完整。

## 已确认规则

1. 学员正在练的计划只要还有未结算训练日，新计划发布、重新发布、日期变化、刷新或重启都不将它替换。
2. 当前计划的全部训练日完成后自动接下一份已发布计划。不以到达某个日历日期作为开关，不复活按日历强制推进。
3. 学员可以主动提前切换。切换不删除原计划、训练记录、视频，不把未练的日子伪造为“已完成”。

## 具体行为提案

### 正常接续

- 一个学员在一次绑定内只有一份“正在练”的计划；服务端保存选择，iOS / Android / 换机一致，客户端缓存只服务离线。
- 新发布的下一周期进入待接续列表，当前训练界面保持原周期、原选中日和已录入数据。
- 待接续计划按 `start_date`、`created_at`、`id` 稳定排序，选择下一周期；重新发布不重排接续顺序。早于当前周期、曾被主动切走的旧计划不自动回到队首，仍可手动选择继续。
- 全部完成指真实训练日都有服务端 completion；休息日不计入分母，空计划不能触发连续自动跳转。
- 最后一节结算成功后，原有奖励、回顾、撤销界面仍指向刚完成的那一天；关闭奖励后可见“本周期已完成，下一周期已接上”。下一次进入训练或点“继续下一节”加载新计划的首个未完成日，不在填写、拍摄或上传中途替换页面。
- 没有下一份已发布计划则显示现有周期完成态；后来发布下一份时自动接上。
- 自动接续后若撤销旧周期最后一天：新周期尚无训练记录时恢复旧周期；新周期已开始则保留当前周期并允许手动回旧周期。不得清掉新周期的记录。

### 主动切换

- 训练页顶栏保留 `W5` 大标题与现有右侧控件，在周次下增加一行可点的计划名 / 日期与下拉符号。整个入口至少 44pt 高，使用现有浅色 / 深色 token。
- 点开原生 sheet“切换计划”，分组显示“正在练”“接下来”“以前的计划”。每行显示名称、起始日期、总周数、已完成节数；当前项勾选。完成进度来自 API，不从日期推断。
- 点其它可练计划，确认文案：“当前计划还有 4 节未完成。切换后记录会保留，也可以回来继续。”按钮“继续当前计划” / “切换计划”。4 为示例，实际读取未完成节数。
- 旧计划若仍为 published，可在同一入口切回，落到它的首个未完成日。paused / completed / 不属本人或当前绑定的计划不能成为正在练的计划；旧已结算日的查看与撤销权限沿用既有规则。
- 切换失败留在原计划并给重试，不先切界面再吞错误；取消不改变任何状态。

### 存量首次使用（待确认）

- 旧版本没有显式的“正在练”记录，不能从“最早未完成”或“最后发布”可靠推断用户意图。
- 服务端无选择记录且只有一份可练未完成计划：直接初始化它。
- 服务端无选择记录且有多份可练未完成计划：首次进入展示上述列表，标题改为“选择正在练的计划”，说明“选一次，之后练完会自动接下一份”。用户显式选择后保存；不默默回卷历史，也不把旧版显示的新计划视作用户已经主动切换。
- 无未完成计划：显示最近周期完成态，下一份到来后正常接续；无 published 计划沿用空态。
- 受影响学员可在首次选择中恢复 10/19 计划，原有完成进度、组记录和视频按原 ID 读取。
- 无网络且有本地缓存时仍可继续原缓存训练，不用在线选择拦住已有训练；联网后再处理未初始化选择，保留待同步写入。无缓存且离线显示可重试状态。

## 技术边界与测试 seam

- **backend 公开 API**：在现有 `/students/:studentId/plans` 列表契约之外新增绑定级选择 / 查询契约，响应包含当前选择、可选计划摘要、完成数和版本。切换必须鉴权并带预期版本，冲突重拉；发布和完成的并发不能把人工选择覆盖。确切路由与字段在 backend 实装卡固定，再以同一组契约 fixture 驱动两端。
- **iOS `StudentPlanRepository` 公开边界**：读取当前计划、刷新、完成日与切换后重读，结合 HTTP fixture 验证真实投影和缓存，不只测 comparator。`TodayWorkoutViewModel` 验证切换时记录 / completion / 视频仍绑定原 dayID 与 exerciseID。
- **Android 公开仓储及训练 screen**：消费同一服务端选择和 fixture，验证冷启、刷新、主动切换、完成接续；不能保留另一套“最后发布”排序。
- **视觉 / 交互**：iPhone 17e 最新 iOS runtime，深浅色、Dynamic Type、简繁英；Android 使用该仓允许的验收设备。完整持久化验收必须经过真实 API，Demo 只证明布局。
- completion 提交和自动接续必须幂等；结算仍在本地待同步时不提前选下一计划。切换不能清离线队列、删除视频文件，或把晚到响应应用到另一周期。
- schema 仅 additive；正式迁移号在实装前查目标分支、open PR、已应用账本再分配。首轮不自动回填“正在练”指针，不更新历史完成状态。部署前备份与回滚方案随 backend 卡审查。
- 旧客户端继续使用原 API，其“最新发布”行为无法靠新增字段修好。必须在新客户端中启用；上线说明明确版本边界，不能把后端部署当作旧包已修复。

## 开发前验收清单

- [ ] A：旧周期剩 4 节，发布未来新周期，刷新 / 杀进程 / 换设备后仍显示旧周期及剩余日。
- [ ] B：只做完部分组、不结算，或只过了推荐日期，不切计划。
- [ ] C：完成最后一节，原日奖励 / 回顾保持正确；随后新周期首个未完成日可练；重复请求不重复接续。
- [ ] D：连续两份待接续计划按周期顺序衔接；重发布、编辑旧计划不抢占当前周期。
- [ ] E：主动提前切换 / 取消 / 切回旧计划；组、完成记录、视频数量与 ID 不变，不伪造旧周期完成。
- [ ] F：无新计划、全完成、空计划、暂停、解绑、无权访问、切换请求失败有确定结果。
- [ ] G：升级时存在多份未完成历史，不猜旧周期；选择一次后重启 / 换机不再询问。反馈中的 10/19 与 11/23 场景可恢复旧周期。
- [ ] H：离线半练 / 最后一节待同步 / 视频上传中切换或重启，重连后数据仍落原训练日且无丢失。
- [ ] I：两台设备同时切换、完成与发布并发，版本冲突可恢复，无跨账号 / 跨绑定串状态。
- [ ] J：自动接续后撤销旧周期最后一天，覆盖新周期尚未开始与已记录两支，符合上述规则。
- [ ] K：深浅色 / 简繁英 / 大字模式入口可点、不遮挡 W#、周条、体重栏和底部完成按钮。
- [ ] L：老客户端 API 兼容；迁移可回滚且未写坏任何原计划、日志、completion、视频关系。

## 实装拆分

每仓一个可独立审查交付单元：backend 的选择与接续状态、iOS 的仓储与入口、Android 的对等实现。共三仓是因为需要持久化选择与双端一致，不按 View / ViewModel 机械拆卡。每卡开头读取对应 CONTEXT，复用本验收清单；先确认共同 fixture 再按行为 red → green。执行时各仓各一个写者，主代理负责；独立 Standards / Spec 收货按 review-loop。

本阶段只交付规则 / 结构稿，不建立未获分配的 backend 迁移或触碰线上账户。产品稿确认后再写各仓实施卡、固定 API 契约并开发。

## Out of Scope

- 不恢复 061 学员顺延，不按日期强迫换周期。
- 不改计划内容、教练发布流程、日志 / 视频归属、已结算日编辑窗口。
- 不引入教练强制切换、批量切换、计划复制、删除、自动补完成或收费限制。
- 不重做训练页 / Tab / 历史页，不复活其他 deferred 项。
- 不直接修改反馈学员数据，不将本稿当作生产迁移、合并或 Archive / Upload 授权。
