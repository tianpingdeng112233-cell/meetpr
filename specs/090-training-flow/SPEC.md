## 术语

- **做完的动作**：这个动作在当天的每一组都有了结果（完成或标记未完成 / 失败），即每组都满足现有的 `isDraftTerminal`，且不是系统代填（`assumed`）。只看当天这一个训练日。
- **正在做的动作**：按计划顺序第一个还没做完的动作，即 hero 卡现在展示的那个（现有 `active` 的取法不变）。

## 已拍板口径

| 题 | 结论 |
|---|---|
| 1 全部记完后完成按钮在哪 | 「长按 · 完成今日训练」吸在屏幕底部、tab 栏上方，不用滑。没全部记完时维持现状 |
| 2 前进感（动作之间） | 页面自上而下：做完的动作（收成一行、标已完成）→ hero 卡（正在做的动作）→ 其余动作。一个动作做完即上收，下一个顶进 hero。主项、变式、辅助项同样处理 |
| 4 前进感（同一动作的组之间） | hero 卡里加一排细分段条（Today 顶部周进度那条的同款），记完一组填实一段，不写成绩 |
| 5 全部记完时 hero 位置 | hero 卡消失，页面是一列做完的动作，底部吸着长按按钮 |
| 3 录入页拍摄行 | 顺序不变，主要压矮「重量」「次数」两行，使拍摄行首屏可见；以 David 的手机（vivo X200 Pro）为准，更小的屏允许仍需少量下滑 |

## §1 做完的动作上收

只作用于"记录态 + 可编辑"的当天训练。只读预览、已结算训练日的详情、未开始时的汇总卡（`Today's workout` 列表 + `Start first set`）一行都不变。

- **分区**：现有 hero 卡下方那一列动作卡，按是否做完拆成两段。做完的排在 hero 卡**上方**，其余（含正在做的那个动作自己的组表卡）留在 hero 卡下方。两段内部都按计划顺序（`sort_order`）。
- **做完的一行**：收起态显示对勾、动作名、`{n} sets`（中文"{n} 组"）与 `Completed`（中文"已完成"）；样式取屏幕稿。点一下展开，展开后的内容与能力和现在的动作卡完全一样（看各组、点组进完整录入页改成绩 / 换视频、辅助项取消记录）。默认收起（沿用现有"刚做完自动收起"的逻辑）。
- **上收的时机**：某动作最后一组有了结果的那一刻。若同一操作让多个动作同时做完（辅助项"全部按计划完成"、跳着记），一并上收。
- **退回**：做完的动作里有一组被取消记录（辅助项再点 ✓、或经录入页改回未记录）→ 它不再算做完，回到下方原顺序位置；若它成为第一个没做完的动作，就重新进 hero。
- **跳着做**：学员先去记了后面的动作——那个动作做完照样上收；前面没做完的仍是 hero。部分记录的动作留在下方，不上收。
- **滚动位置**：上收后页面自动滚到"刚收上去的那一行"贴近可视区顶部——它和紧随其后的 hero 卡同屏可见，更早做完的行在上方、上滑可见（10/10 实屏后修订：原写"滚到 hero 卡顶"，那样刚做完的行被滚出屏幕，看不到"已完成"）。学员正在手动滚动或软键盘开着时不抢滚动。
- **动效**：上收与顶替各一次短过渡，属于"反馈"类动效（符合现行动效口径：只留反馈与奖励）；系统"减少动态效果"开启时直接切换。
- 读屏：做完的一行读"`Squat`, completed, 3 sets"（中文"已完成，3 组"），可展开状态照常播报。

## §2 hero 卡：组进度分段条

- 位置与样式取屏幕稿；分段数 = 该动作当天的组数，顺序即组序。
- 一段的三种状态：已有结果（填实）、当前要做的这一组（高亮）、还没到（空）。标记未完成 / 失败的组也算已有结果，用弱一档的填充与完成的组区分；不用红色。
- 记完一组：对应段填实，高亮移到下一段，一次短过渡。
- **只在主项 / 变式的 hero 形态出现**。辅助项记录卡已经逐行显示完成状态，不再加分段条。
- 现有那行 `Set 2 of 3 · exercise 1 / 5` 小字保留（分段条不替代它的读屏信息）；分段条本身对读屏隐藏。

## §3 全部记完：hero 消失、按钮吸底

- 当天所有动作都做完时：hero 卡不再渲染；页面是做完的动作一列。
- 「长按 · 完成今日训练」按钮固定在屏幕底部、tab 栏上方，带与页面背景一致的底衬，滚动内容不被它遮住最后一行（列表底部留出等高的空白）。长按的行为、触感、进度、结算与庆祝页全部不变。
- 滚动区底部原来那颗按钮在此状态下不再出现（全页只有一颗）。
- **没全部记完时维持现状**：已记过至少一组后，按钮与"还剩 {x} 个动作 {y} 组"的提示仍在滚动区底部，不吸底。
- 吸底后又取消了某组记录（不再是全部记完）→ 按钮回到滚动区底部，hero 卡按 §1 的退回规则重新出现。
- 休息计时条若此时还在走（不常见：最后一组不起计时），吸底按钮排在计时条上方，两者不重叠。

## §4 组录入页：拍摄行首屏可见

- 各段顺序不变：配片图 → 上赛扣 → 重量 → 次数 → RPE → 视频（Record / Photos）；「完成本组」「未完成 / 失败」仍吸底。
- 主要压矮「重量」「次数」两行（数值框、加减按钮、标题与步长说明所占的高度，以及段间距）；配片图与 RPE 刻度的调整幅度取屏幕稿。可点控件的命中高度不低于 44。
- 目标：在 David 的手机（竖屏、默认字体大小）上打开录入页，不滑动就能完整看到 Record / Photos 那一行。更小的屏允许仍需少量下滑；系统字体放大时不保证。
- 数字键盘、长按连加、配片图随重量变化、已选视频的状态显示等行为全部不变。

## 存量数据与升级

- 纯展示层改动，不读写新字段，不动本地存储键。升级后进训练页：已记过若干组的当天训练，直接按 §1–§3 的规则排好（做完的在上、正在做的在 hero）；不出现上收动效（动效只在本次运行内"刚做完"时播）。
- 已结算的历史训练日、Training history、Today 页不受影响。

## Out of Scope

iOS；Today 页；未开始时的汇总卡；只读预览与已结算详情；辅助项记录卡内部（089 已定）；录入页各段的顺序与功能；没全部记完时提前结算的入口与提示；休息计时；任何后端改动。

## 测试 seam

优先纯函数，取最高层、越少越好：

- **S1 分区**（新纯函数，输入现有的动作分组与 drafts，输出"做完的 / 正在做的 / 其余"三段）：全没做、做到一半、跳着做、部分记录、含失败组、含 `assumed`、全部做完、做完后取消一组，各一条断言。
- **S2 分段条模型**（新纯函数，输入一个动作的 drafts，输出每段状态）：0/3、1/3、含失败、全部完成。
- **S3 完成按钮形态**：扩展现有 `completionAvailability`（`hold-to-complete.ts`），在原有 `button` / `pill` 之外给出"是否吸底"；原有断言不改，新增"全部记完 → 吸底且无 pill""差一组 → 不吸底"两条。
- **S4 页面层**（现有训练页组件测试的同一 seam）：做完第一个动作后，它出现在 hero 之前并带已完成标记；全部做完后 hero 不在、吸底按钮在；取消一组后恢复。
- 录入页压矮是纯样式，不加快照测试；由 Opus 在模拟器与 David 真机上看。

## 验收清单（开发前定，Opus 逐项收货）

1. 当天训练一组未记：页面与现在一致，hero 上方没有任何做完的行；主项 hero 卡有分段条，全空、第一段高亮。
2. 记完主项第 1 组：分段条第一段填实、第二段高亮；动作仍在 hero。
3. 记完主项最后一组：该动作收到 hero 上方，显示已完成；下一个动作进 hero；页面滚到 hero 完整可见。
4. 点开做完的一行：能看各组、点组进录入页改成绩；关掉后状态不乱。
5. 辅助项：逐组打 ✓ 到最后一组、以及"全部按计划完成"，都会上收；辅助项 hero 卡没有分段条。
6. 对做完的辅助项取消一组：它回到下方；若它排在最前则重新成为 hero。
7. 跳着做：先把第三个动作全记完 → 它上收，hero 仍是第一个没做完的。
8. 全部做完：hero 消失；长按按钮吸在 tab 栏上方，列表最后一行不被遮住；长按能正常结算并出庆祝页。
9. 全部做完后取消一组：按钮回到滚动区底部，hero 重新出现。
10. 只做了一部分：按钮与"还剩…"提示仍在滚动区底部（与现在一致）。
11. 带历史的老用户升级后第一屏：当天已记 5 组的训练，打开即是正确分区，无动效、无跳动。
12. 未开始汇总卡、只读预览、已结算详情、Training history：与改动前逐屏一致。
13. 录入页：模拟器（Pixel 默认尺寸）与 David 真机上不滑动可见 Record / Photos；加减、数字键盘、配片图、RPE 刻度、拍摄、相册均可用。
14. 深色、中文、磅单位各看一遍 1–3、8、13。
15. `npm test -- --runInBand`、`npx tsc --noEmit`、`npm run lint` 全绿；既有测试的断言不删不改（确需改的逐条在 JOURNAL 说明原因）。

### A · hero 卡的组进度分段条（主项 / 变式）

### B · 做完的动作收到 hero 上方
