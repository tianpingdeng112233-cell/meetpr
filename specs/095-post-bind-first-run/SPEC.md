- 对应编号：iOS/安卓 `095-post-bind-first-run`（两端共用正典在安卓仓 `meetpr-rn`，本文为 iOS 仓镜像，以安卓仓为准）；后端 `055-bind-accepted-push`。

## 现状（2026-10-23 两端代码核实）

| 环节 | 现在 | 问题 |
|---|---|---|
| 待接收 → 接受 | 安卓 `BindGate` 只在 App 切回前台时重查；iOS 同理。接受后直接换成主界面 | 学员开着 App 等，看不到已被接受；接受那一刻没有任何反馈 |
| 接受通知 | 后端接受时只给教练端有推送（`bind_request`），不给学员发 | 学员不知道该回来了 |
| 评估期 | `evaluationSealed = true`（2026-07-13 封），spec 033 代码休眠 | 本期不动 |
| 无计划时首页 | `DashboardPlanWaitingState`：「{教练}正在为你排 W1」「会参考你这周的 RPE 和完成情况 · 通常周日 21:00 前发布」「给教练留言」「本周小结 · W1」三格「—」 | 这张卡是为「两周之间」写的；新学员没有 RPE，「周日 21:00」是空头承诺，空小结无意义 |
| 计划到达 | 首页直接变成 W1D1 +「开始训练」，无任何提示；iOS 有 `plan_published` 推送，安卓 RN 未注册任何推送 | 第一份计划到达这个时刻被浪费 |
| 通知权限 | iOS 登录后 App 一激活就弹系统权限框（`PushRegistrationStateMachine.actionsForActivation`） | 弹时学员还没绑定、不知道为什么要开；点了「不允许」以后计划推送也收不到 |

## 共识（David 2026-10-24 拍板，实装中不得改动）

1. **欢迎页**：接受后一次性全屏欢迎页（Q1A）。以「一次绑定」为单位：本次绑定还没结算过任何训练日、且本机没看过 → 出现；换教练重新绑定会再出现（Q7A）。一屏：「你现在是{教练}的学员了」+ 三步（教练排计划 → 计划出现在今天 → 练完记录）+「进入」。
2. **待接收页感知**（Q2A）：页面在前台时每 30 秒重查一次绑定状态；后端新增「教练已接受」推送（只 iOS 收得到）。
3. **通知权限时机**（Q4A + Q8A，仅 iOS 学员）：不再在登录后自动弹。改为两处由学员点按钮触发：待接收页「教练接受后提醒我」；欢迎页「教练发计划时提醒我」（只在学员还没被问过时出现）。
4. **新学员等计划卡**（Q3A + Q9B）：本次绑定还没收到过任何计划时，首页的等计划卡换成新学员版：标题「{教练}正在为你排第一份计划」；不写发布时间；去掉「本周小结」；保留「给教练留言」；加两条引导「完善资料」「填比赛日」。老学员在两周之间（本次绑定已收到过计划、当前没有可练的计划）仍看原卡，逐字不变。
5. **第一份计划卡**（Q5A + Q10A + Q11A）：本次绑定的第一份计划到达后，首页出一张卡「教练发布了你的第一份计划」+「W1–W{n} · 共 {m} 节」+「开始 W1D1」+ ×。学员点「开始」或 × 后本机不再出现。学员首次进主界面时计划已经发好 → 先欢迎页，点「进入」后首页出第一份计划卡（不经过等计划状态）。只管第一份，之后每份新计划的提醒不在本期。
6. **评估期继续封存**（Q6A）。

## 判定口径（两端必须一致）

- **一次绑定**：学员当前那条 `status = accepted` 的 `bind_request`，以它的 `id` 为键。换教练重新绑定 = 新的一次绑定。
- **本次绑定的计划**：由本次绑定的教练（`bind_request.coach_id`）发布、发布时间不早于 `bind_request.responded_at` 的计划。字段以实际 API 为准，若现有出参判断不了，在 PR 里写明并回报，不得改用别的口径。
- **欢迎页出现条件**：处于本次绑定 && 本机没看过（本地键 = 学员 id + bind_request id）&& 本次绑定的计划里没有任何一天已结算。
  - 说明：共识 1（Q7A「还没收到过计划」）与共识 5（Q10A「首次进来时计划已发好也先出欢迎页」）合起来，口径落为「还没结算过任何训练日」。这样带历史的老学员升级后不会看到欢迎页。
- **第一份计划卡出现条件**：本次绑定有第一份计划 && 这份计划里没有任何一天已结算 && 本机没关闭过（本地键 = 学员 id + bind_request id）。
- **新学员版等计划卡出现条件**：首页处于现有「等计划」状态（当前计划没有可练的天）&& 本次绑定没有任何计划。否则显示原卡。
- **「填比赛日」引导**：学员资料已有比赛日时隐藏；「完善资料」常显，进「我的资料」。
- 换设备或重装：本地键丢失，若仍满足条件（没结算过训练日 / 第一份计划没开始）会再出现一次，可接受。

## 各处行为

### 待接收页（两端）
- 页面可见且 App 在前台时，每 30 秒调一次 `GET /bind-requests/mine`；进后台即停，回前台立刻查一次（保留现有行为）。
- 查到 `accepted` → 进入主界面流程（欢迎页判定）。
- iOS：通知权限为「未决定」时显示文字按钮「教练接受后提醒我」，点了弹系统框；已允许或已拒绝时不显示。安卓不显示。

### 欢迎页（两端，全屏，一次性）
- 元素：教练显示名（有头像就显示头像）、小字「绑定成功」、标题「你现在是{教练}的学员了」（David 10/24 定）、三步说明、主按钮「进入」。
- 标题拼名规则：显示名已含「教练」就不再追加（「王教练」→「你现在是王教练的学员了」）；否则追加「教练」（「王磊」→「王磊教练」）；显示名为空 →「你现在是教练的学员了」。英文：「You're now training with {name}」，为空时「You're now training with your coach」。
- iOS：通知权限为「未决定」时，在「进入」上方多一个按钮「教练发计划时提醒我」；点了弹系统框，不管结果都留在欢迎页，学员再点「进入」。安卓无此按钮。
- 点「进入」→ 写本机已看过 → 主界面（今天 tab）。

### 首页等计划卡（两端）
- 新学员版：标题、说明一句（不写时间）、「给教练留言」（沿用现有跳转）、「完善资料」→ 我的资料、「填比赛日」→ 现有比赛日编辑入口（与首页「距比赛 · 填写比赛」同一跳转）。没有「本周小结」块。
- 老学员版：原卡逐字不变。

### 第一份计划卡（两端）
- 位置：今天 tab 顶部，计划内容之上。
- 元素：标题「教练发布了你的第一份计划」、「W1–W{n} · 共 {m} 节」、主按钮「开始 W1D1」、右上角 ×。
- 「开始 W1D1」→ 与首页现有「开始训练」同一路径打开训练页并写本机已关闭；× → 写本机已关闭。

### iOS 通知权限
- 学员角色（`coached_student`）：激活时权限为「未决定」→ 不再自动请求；只在上面两个按钮里请求。权限为「已允许」→ 照旧注册设备令牌（老用户零变化）。
- 教练角色与自主训练学员：维持现状（激活即请求），本期不动。

### 后端（055，详见后端仓 spec）
- 教练接受绑定成功后，给学员入队一条 `bind_accepted` 推送（失败不影响接受接口）。文案中文「{教练}已接受你的申请」/「打开 MeetPR 看看接下来做什么」，英文与繁体照现有推送规则出。
- 老版 iOS 收到未知 `kind` 时路由为空、只打开 App（已核实 `PushNotificationRouting` 对未知 kind 返回 nil），不需要兼容处理。

### 文案
- 新文案出简体、繁体（台湾，按 spec 094 的生成流程与覆写表）、英文三套。最终措辞以定稿的屏幕稿为准。

### 埋点
沿用两端现有 analytics 机制，新增：欢迎页展示 / 点进入；通知权限按钮点击（来源：待接收页 / 欢迎页；结果：允许 / 拒绝）；第一份计划卡展示 / 点开始 / 点 ×。事件名按各端现有命名规范定。

## 验收清单（Opus 收货逐项过，实装方不得自定）

1. 新学员全程（两端各一遍，模拟器）：注册 → 填码 → 资料向导 → 待接收页 → 教练在另一端接受，学员不切后台 ≤30 秒内自动进入欢迎页 → 点「进入」→ 首页显示新学员版等计划卡（无周小结、无「周日 21:00」）→ 教练发布计划 → 回到首页出现第一份计划卡 → 点「开始 W1D1」进入训练页 → 返回首页卡不再出现。
2. 首次进主界面时计划已发好：先欢迎页，点「进入」后直接是第一份计划卡，不出现等计划卡。
3. iOS 通知权限：全新安装的学员登录后不弹系统框；待接收页按钮点击弹框；拒绝后欢迎页不再出现权限按钮；已允许的老用户升级后照常收推送。教练账号登录行为不变。
4. iOS 推送：学员在待接收页、App 在后台时，教练接受 → 收到「{教练}已接受你的申请」，点开进入欢迎页。
5. **老用户升级第一屏**：带训练历史的已绑定学员覆盖安装新包 → 首页与升级前一致，不出欢迎页、不出第一份计划卡；两周之间等计划的老学员仍看原卡逐字不变。
6. 换教练：学员解绑后重新绑定新教练 → 再次出现欢迎页，标题是新教练的名字；新教练的第一份计划再次出第一份计划卡。
7. 「填比赛日」：资料已有比赛日时不显示；没有时显示，点了进入比赛日编辑。
8. 繁体系统下新增各屏零简体字；英文系统下新增各屏为英文。
9. 两端全量测试绿；后端接受接口在推送入队失败时仍返回 200。
