## 1. 愿景 / One-liner

> **替代力量举圈微信 + 在线表格的协作工作流，让教练-学员关系在结构化产品里完成。**

更长版本：MeetPR 是力量举垂直领域第一个面向**中文市场**的双端 iOS app。教练在 app 内编排训练、查看学员状态、对视频做动作维度反馈；学员在 app 内接收计划、记录训练、上传视频、看自己的进步曲线。

**三阶段路径**（v0.5 修订）：
- **V1**：**B2B 教练-学员工作流闭环 + B2C 自己练模板模式**（内测 phase 1 = B2B core，phase 2 = B2C 模板接入；公测双模式齐发）
- **V2**：算法生成训练计划（对标 Juggernaut AI 中文版，从模板 + 参数化进化到周期化算法）+ ADR 002 智能数据分析完整化
- **V3**：Marketplace——学员在 app 内寻找心仪教练，平台提供撮合

## 2. 目标用户

### 2.1 V1 主要用户：教练（B2B 付费方）

**画像**：
- **核心群体**：带 5+ 学员的力量举/体能教练（调研 89% 教练带 5+ 学员）
- **现实抓手**：手上 10+ 个意向中大体量教练（office hours 2026-04-25 确认）
- **当前工具栈**：100% 用在线表格（94% 飞书/腾讯文档/石墨 + 6% Excel）+ 78% 用微信发视频/语音/文字反馈
- **典型痛点**（调研原声）：
  - "学员一次过发太多视频，不标注组数重量，回复压力大"
  - "动作完成情况的文字描述、具体数据和视频难以清楚一一对应"
  - "收集到的数据没有好的分析方式，无法很好的指导决策"
  - "看前边的训练比较麻烦"
  - "学员掌控不了 RPE，乱冲，然后试举失败"

**目标行为变化**：
- **From**：每天碎片时间在微信里翻 30+ 学员的视频、对照在线表格找今天该看哪个、文字反馈贴回学员
- **To**：打开 MeetPR，看本日待处理队列（按学员/动作/重要度排序），每条反馈 ≤30 秒完成

### 2.2 V1 次要用户：有教练的学员（B2B 免费侧）

**画像**：
- 力量举/体能专项学员，已绑定线下/线上教练
- 当前通过线上表格（90%）接收计划，靠"今天状态感觉"（59%）/ 上次重量（38%）/ 问教练（20%）选今日重量
- 反馈方式：发视频（66%）+ 文字（67%）+ 线下（23%）
- 年龄分布：未在调研中明确，**V1 假设全部 ≥18 岁**（详见 §8.7 未成年人）
- **里欧的学员群体**作为 V1 内测候选：年轻、有海外客户（先验海外节点访问的需求）

**功能范围**（v0.5）：本类学员看到"有教练模式"——接收教练计划 + 执行 + 上传视频 + 接收教练反馈 + 看成长曲线。**免费**。

### 2.3 V1 第三类用户（v0.5 新增）：自己练学员（B2C 付费方）

**画像**：
- 力量举专项爱好者，没有线下/线上教练，想用既定 program 自训
- 通常已知 1-3 个欧美主流模板（如 5/3/1, GZCL）但用 Excel 自己跟踪
- 海外学员场景里这类比较多（里欧海外圈层先验）
- 年龄假设 ≥18

**功能范围**（v0.5）：本类学员看到"自己练模式"——从 10-15 个欧美主流模板里选 program + 设置 1RM + 系统按模板生成训练计划 + 执行 + 看成长曲线。**付费订阅**（参考 JAI £30.49/月，国内定价待研究）。

**注意**：自己练模式不含教练反馈、不含视频反馈队列。如学员后续想要教练，可在 V3 marketplace 中寻找（V1 不开放转化路径）。

### 2.4 V2/V3 扩展用户（路线图占位）
- **V2**：自己练学员升级——从模板 + 参数化进化到算法生成（基于 e1RM + 周期化模型）
- **V3 Marketplace 用户**：学员在 app 内浏览/搜索/匹配教练；教练通过 public profile 接收学员请求。详见 §11.

### 2.5 明确不是目标用户（V1 不服务）
- 健身房综合体能爱好者（不专注力量举三大项）
- 注重营养追踪 / 围度变化 / 进展照片的用户
- Android / Web 端用户（V1 仅 iOS，详见第 10 节）
- 不带学员或仅带 1-2 学员的个人教练（不在中大体量画像内）
- 未成年学员（V1 暂不开放，详见 §8.7）

## 3. 核心价值主张

| 角色 | 一句话价值 | 用户接收信号（V1 评估期） |
|---|---|---|
| 教练 | "微信不用了，所有训练数据、视频、反馈都在 MeetPR" | 每周清"反馈队列"耗时 ≤ 当前微信操作 60%；教练满意度 ≥ 8/10 |
| 学员 | "训练历史不再丢，进步看得见" | 主动打开 app 看成长曲线（每周 ≥2 次）；30 日留存 ≥ 40%（H4 待验证）|

> **注**：v0.1 提到"复盘耗时减半（5h → 2.5h）"已删除——V1 P0 不含教练侧"周复盘汇总视图"，无法支撑该数字。教练侧周复盘视图列入 V1.5（详见 §5 P1）。场景 1 中的"3h → 1-1.5h"也是直觉估算，需 V1 内测期实测后修正。

**为什么不是又一个 workout tracker**：MSB 主体是单端学员 app（v0.3 更正：MSB 实际**有**教练端，但中文市场不可达——既无中文化也无中国分销），JAI 是单端 AI app（无教练）。**MeetPR 是面向中文市场的力量举垂直第一个真正的双端原生 iOS app**——这一表述比 v0.2 的"全球第一个"更精确，依据见 §12 ADR 003 触发的 review 注释。

**为什么不是又一个 AI 健身 app**：调研推翻了"AI 优先"假设。教练 #1 需求 = 学员数据 + 视频归档；学员 #1 需求 = 训练数据存档 + 成长曲线。AI 排第 3-10。V1 完全不做 AI（详见 ADR 001）。**V2 的"自己练"训练计划生成，优先用算法（基于 e1RM + 周期化数学模型）而非 AI；AI 仅作为算法无法覆盖的 fallback**——这是 v0.3 对 ADR 001 边界的细化。

## 4. 使用场景（V1 关键流程）

### 场景 1：教练周日晚为下周排计划

**Before**（现状）：教练打开飞书表格，复制上周模板，按 30 个学员一个一个改。3 小时（直觉估算，待 V1 内测实测）。
**After（V1）**：教练在 app 内打开"计划编排"，**为每个学员"复制上周计划→修改"**（V1 不做模板库、不做批量下发——这两个延到 V1.5）。预期：30 学员从 3 小时压到 1-1.5 小时（**直觉估算，V1 内测期实测验证**）。

**关键交互**（V1 范围）：
- 单学员视图：本周计划 + "复制上周" 一键操作 + 各组重量/次数/RPE 编辑
- 不在 V1：跨学员模板库 / 批量参数修改 / 一键群发

### 场景 2：学员训练时执行 + 上传视频

**Before**：学员看飞书表格，做完一组随手用微信发视频给教练，靠记忆补一句"刚那组 RPE 8.5"。
**After**：学员在 app 内打开今日训练，每组做完点击"完成"录入重量+次数+RPE，重要组直接 app 内拍视频上传（自动绑定到这一组）。

**关键交互**：
- 训练页面：当日动作清单 + 每组的"重量/次数/RPE"录入（RPE 滑块 0.5 步进，默认值预填上次同动作 RPE）
- 视频拍摄：直接 app 内调相机或选相册（**默认 60s，最大 90s**——容纳大重量动作长准备时间）
- 视频自动绑定到具体的"动作-组次"，不需要学员手动标注
- 离线行为：训练数据 + 视频 enqueue 本地，恢复网络后自动上传（详见 §8.8）

### 场景 3：教练通勤时清反馈队列

**Before**：教练打开微信，30 个学员的视频混在一起，要先翻聊天找今天的、再找视频对应哪个动作。
**After**：教练打开 MeetPR，"待反馈"队列按学员/紧急度排序，点开每条视频已经标注"张三 · 周三 · 深蹲 · 第 4 组 · 100kg×5 · RPE 8"，30 秒打字反馈。

**关键交互**（V1 范围）：
- 反馈队列页：按学员卡片/视频缩略图/已等待时长排序
- 视频播放页：标准信息标注 + 教练**文字反馈框**（V1 不含语音反馈——延到 V1.5）
- 反馈已读 / 未读状态同步学员端
- 视频播放：标准 AVPlayer + 倍速控制（0.5x / 1x / 1.5x / 2x）

### 场景 4：学员周日复盘 + 看成长

**Before**：学员翻飞书表格的历史 sheet，几乎不看（"看前边的训练比较麻烦" — 调研原声）。
**After**：学员在 app 内打开"成长"，看三大项（深蹲/卧推/硬拉）的 e1RM 折线图 + 本周训练完成度。

**关键交互**：
- 三大项 e1RM 折线（基础版，**单条平均线**——ADR 002 的峰值/平均分离延到 V1.5，详见 §5 P0 #10 的注释）
- 本周完成度环形图
- "看到自己进步"是主动打开 app 的核心动机

### 场景 5：教练查看学员状态面板

**Before**：教练在脑子里维护"哪个学员这周还没完成"、"哪个学员状态在下滑"——靠记忆。
**After**：教练打开 MeetPR，学员状态面板按"完成度 / 待反馈视频数 / 上次活跃时间"排序，一眼看到需要主动联系的学员。

### 场景 6（v0.6 新增）：教练接收新学员 + 评估期 funnel

**Before**：肖天宇朋友圈推荐学员小明 → 加微信 → 让小明发训练史 → 看一眼 → 直接发计划。质量不可控。
**After（V1）**：肖天宇生成 personal 永久邀请码 → 小明扫码注册 → 完成 onboarding（含上传视频/计划）→ 进肖天宇接收队列 → 肖天宇查看摘要 → 接收 + 进入 7 天评估期 → 期内看视频 + 发适应周 + 留言 → 评估完成填 3 字段评估总结 → 学员收到摘要+一键展开 → 软推荐排首份 4 周计划。

**关键交互**（V1 范围，详见 [[evaluation-workflow]]）：
- 教练接收队列 tab + 摘要卡片 9 项 + [接收 ▼ 进评估期 / 跳过] / [拒绝]
- 7 天评估期硬截止（超期 36h 催 1 次）
- 评估总结 = 3 自由文本字段（整体评估 + 训练规划 + 给学员的话）
- 学员端"评估进行中"状态 + 教练已查看资料计数 + 适应周训练（如有）
- 评估完成 → 学员收到摘要推送 + 教练弹"立即排首份计划 / 稍后"软推荐

**关键交互**：
- 学员卡片列表：头像 + 本周完成度 + 待反馈数 + 异常标签（如"3 天未训练"）
- 点开进入单个学员详情页（与学员端"自己看自己"复用同一组 SwiftUI 组件，仅权限层不同）

#### 教练端 P0（B2B）
1. **学员管理 + 邀请码体系**（v0.6 升级）：
   - 邀请码 3 类：Personal 永久 / 一次性 / 限时（详见 [[evaluation-workflow]] §2）
   - 解绑学员（任一方可单方触发，无需对方同意）
   - 按组分类
2. **接收队列**（v0.6 新增）：
   - 学员扫码后进"新学员请求" tab
   - 卡片摘要 9 项 + 一键展开完整资料
   - [接收 ▼] 弹模态 2 选 1：进 7 天评估期 / 跳过评估期（熟人）
   - [拒绝] 中性 silent，无填原因要求
   - 详见 [[evaluation-workflow]] §3
3. **评估期工作流**（v0.6 新增）：
   - 7 天硬截止；期内可发适应周不可发正式 4 周
   - 期内能力：看资料 / 文字留言 / 适应周计划
   - 评估总结：3 自由文本字段（整体评估 + 训练规划 + 给学员的话）
   - 软推荐衔接首份正式计划
   - 超期 36h 催 1 次
   - 详见 [[evaluation-workflow]] §4-§6
4. **计划编排**：单学员视图 / 周/月计划编辑器 / 动作库选择 / 重量+次数+RPE 设定 / **复制上周计划**一键操作 / 计划下发
   - V1 不含：跨学员模板库、批量下发、计划进行中编辑（教练改 Wed 后学员 Mon 已完成的处理）
   - V1 行为：教练改未来日期的计划，学员端立即更新；教练改已完成日期的计划，禁止（提示走"反馈"通道）
   - **教练改 cycle 计划的推送规则**（v0.6）：高 level 通知 + 24h 内训练日改动 = 紧迫推送 + 红点提示
   - 编辑器是产品最复杂的页，详见 [[coach-planning|coach-planning v4.1]]
5. **教练改 Type A 锁定字段的 cascade 模态**（v0.6 新增）：
   - Type A 字段 = 1RM / 训练日 / 训练环境（仅教练端可改）
   - 教练保存改动 → 弹模态 3 选 1：①重排 cycle / ②不动（学员侧提醒"档案已更新但当前 cycle 仍按旧值"）/ ③提前结束 cycle
   - 详见 [[coach-planning|coach-planning v4.1]]
6. **学员状态面板**：学员卡片列表、本周完成度、待反馈视频数、最后活跃时间
7. **视频反馈队列**：按时间/学员/紧急度排序、视频播放（带标注信息）、**文字反馈**（V1 不含语音反馈）
8. **学员详情页**：单个学员的本周完成情况、历史训练记录、e1RM 折线、视频历史 + **评估总结编辑入口**（v0.6 新增 - 教练随时可调整评估总结）

#### 学员端 P0 — 有教练模式（B2B）
9. **待接收状态**（v0.6 新增）：学员扫码后立即看到"已发送绑定请求，等待教练接收 + 已等待 X 小时" + [取消请求]；7 天教练未响应自动 expired
10. **评估期状态**（v0.6 新增）：教练接收后进评估期 → 学员看到"评估进行中 + 还剩 X 天 + 教练已查看资料 N/M + 教练留言 + 适应周训练（如有）"
11. **评估总结**（v0.6 新增）：教练完成评估后学员收到摘要推送 → 摘要（训练规划前 1-2 句 + 给学员的话前 1-2 句）+ 一键展开看全文 + 在"我的资料"持久查看
12. **接收计划**：当日训练页、本周计划概览、推送通知
13. **训练记录**：每组的重量/次数/RPE 录入（RPE 滑块 0.5 步进，默认值预填）、完成打勾
14. **视频上传**：每组可选拍摄/选择视频上传（自动绑定动作-组次）、默认 60s 最大 90s、本地队列+断点续传；首次上传弹窗提示"视频将仅你绑定的教练可见"+ 用户同意（同意记录入数据库供合规审计）
15. **训练历史**：按周/月查看历史训练、单次训练详情
16. **成长曲线 + e1RM 推送**（v0.7 PR 重塑）：
    - 三大项 e1RM 折线图（基础版，**单条平均线** —— 见 §5 顶部 ADR 002 状态说明）
    - **PR 检测**（议题 6 决议）：
      - **1RM 字段锁定不动**（仅 onboarding 填 / 教练改 / V2 比赛日触发——不被训练日 PR 改）
      - **e1RM 每次训练后系统自动重算**（基于 RPE-based 公式 / Epley fallback）
      - **e1RM 突破历史最高 → 自动推送学员**（"今天你的 squat e1RM 突破！"）
      - **教练侧不推送 PR**——教练打开学员曲线能看到增长即可
    - 每个动作（含 variation）有自己的 e1RM 历史，独立 PR 检测
17. **教练反馈**：查看教练对自己视频/训练的反馈、推送通知
18. **我的资料 4 级修改权限**（v0.6 新增）：
    - Type A 锁定（cycle 中只读，仅教练端改）：1RM / 训练日 / 训练环境
    - Type B 学员可改 + 立即推送教练：伤病记录新增 / 恢复评估 4 滑块更新
    - Type C 学员可改 silent：想增强肌群 / 比赛日期 / 给教练备注
    - Type D 学员可改 silent（基础信息）：身高 / 体重 / 联系方式 / 单位制
    - 详见 [[student-onboarding|student-onboarding v2.2]]

#### 学员端 P0 — 自己练模式（B2C，v0.5 新增，Phase 2 接入）
19. **模式切换 / onboarding**：账号注册时选择"有教练" or "自己练"；自己练模式独立 onboarding 流程
20. **自己练 onboarding**：
    - 1RM 测试或自填三大项（深蹲/卧推/硬拉）当前 1RM
    - 训练目标选择（增力量 / 增肌 / 备赛 / 综合）
    - 训练频率（3/4/5 天/周）
    - 模板浏览 + 选型（10-15 个欧美主流 program，里欧整理交付，详见 §13.1）
21. **训练计划生成**：基于选定模板 + 用户参数（1RM / 频率 / 周期长度），系统按模板规则展开为可执行训练计划
    - V1 不做：算法生成（V2）/ AI 生成（永不做）/ 个性化偏离模板
    - V1 做：模板参数化 + 周期推进（线性渐进 or 模板内置周期）+ deload 自动插入（按模板规则）
22. **自己练训练执行**：复用 #13 训练记录组件 + #15 训练历史 + #16 成长曲线（同样的 SwiftUI 组件，去掉教练反馈相关）
23. **B2C 订阅入口**：学员端"自己练"模式订阅页 + 7-14 天免费试用 + IAP（详见 §8.3）
    - V1 不做：B2C 学员视频上传（Phase 1 仅有教练学员可上传视频）—— V1.5 评估自己练学员是否需要"复盘视频"功能

#### 双端共享 P0
24. **账号体系 + 单用户单角色**（v0.7.4 反转 — v3 议题 4 多角色 deferred 到 V1.5+）：

    - **V1.5+ deferred reference**（v3 议题 4 决议反转）：

      - ~~主角色 = 教练：可启用副身份"学员"（去训练自己）~~
      - ~~主角色 = 学员：可在"有教练 / 自己练"模式间切换~~
      - ~~每个身份独立的"我的"页 / 数据 / UX~~

    - 学员角色（自己练）：无绑定

    - 教练 → 学员：计划下发 / 反馈到达 / 评估完成 / 计划修改 / 评估总结修改（教练手动选）
    - 学员 → 教练：视频上传完成 / 训练完成 / 学员主动发问 / 学员加新伤病 / 恢复评估更新 / 绑定请求
    - 系统 → 教练：48h 待响应再推 / 评估期超期 36h 再推 / 老教练推荐 bonus 解锁
    - 系统 → 自己练学员：今日训练提醒 / 周期 deload 提醒 / 模板完成

## 6. 非目标（明确不做什么）

### V1 不做（明确砍掉）
- ❌ **任何形式的 AI 或算法生成训练计划** — 详见 ADR 001。**自己练模式 V1 用模板 + 参数化，算法生成 V2**
- ❌ **ADR 002 的智能数据分析**（峰值/平均、次数区间、部位 RPE、智能预警）— 全部延到 V1.5+
- ❌ **自己练学员的视频上传 + 复盘** — V1 仅有教练学员可上传视频；自己练学员看自己曲线即可。V1.5 评估
- ❌ **教练语音反馈** — V1 砍掉，V1.5 评估
- ❌ **跨学员计划模板库 + 批量下发** — V1 砍掉，V1.5 评估（注意：这里指**教练端**的跨学员模板复用，与学员端"自己练"的欧美训练模板是两件事）
- ❌ **微信登录** — V1 砍掉（Apple §4.8 合规研究 + SDK 集成），V1.5 评估
- ❌ **教练侧周复盘汇总视图** — V1.5
- ❌ **Android / Web** — V1 仅 iOS 17+
- ❌ **营养追踪 / 围度变化 / 进展照片** — 不在力量举专注定位内
- ❌ **比赛/Meet 追踪** — 名字里有但 V1 不做（V2 P2）
- ❌ **教练协作 / 团队套餐** — 单教练自带学员模型
- ❌ **第三方平台同步**（Strava / Apple Health 等）
- ❌ **未成年学员**（V1 不开放，V2 评估监护人流程）
- ❌ **Marketplace 教练撮合**（V3）
- ❌ **自己练模式向有教练模式的转化路径** — V1 内不开放，V3 marketplace 才接入

### 永不做（产品边界）
- 综合体能 / 健美 / 强人项目（保持力量举专注，对照 JAI 的 PowerCombo / Strongman 路线明确不走）
- 完整宏量营养追踪（对照 MSB 不走）

## 7. 成功指标

### 7.1 V1 北极星指标（v0.5 双业务）
> **B2B**：教练周活率 × 有教练学员周活率 × 教练付费率
> **B2C**：自己练学员 30 日留存 × B2C 订阅转化率
> 两条北极星各自要 work。任何一条挂掉都说明该业务没跑通。

### 7.2 V1 关键指标（公测 3 个月评估）

#### B2B 指标
| 指标 | V1 目标 | 依据 / 注 |
|---|---|---|
| 教练 MAU | ≥ 6（10+ 意向 ≥60% 转化）| 手上 10+ 教练；肖天宇圈层加成 |
| 教练周活率 | ≥ 80% | 教练每周必须排计划 + 看反馈 |
| **教练满意度** | **≥ 8 / 10**（CSAT 1-10 量表）| v0.1 NPS 单位错已修 |
| 教练 DAU/MAU | 0.4-0.7（低频但高粘）| ADR 003 健康区间 |
| 学员/教练比 | 1:15 ~ 1:30 | ADR 003 健康区间 |
| 有教练学员 7 日留存 | ≥ 60% | 留存靠教练驱动 |
| 有教练学员 30 日留存 | ≥ 40% ⚠️ **未验证假设**，详见 §10 H4 | "看到进步"价值是否成立 |
| 学员每周训练记录次数 | ≥ 3 | 力量举训练频率基线 |
| 视频上传成功率 | ≥ 95%（同一 session 24h 内）| 含断点续传后最终成功 |
| 推送通知送达时延（90 分位）| **≤ 30s（v0.7.2 调整）**| ADR 004 V1 妥协（APNs + polling）；V1.5 升级 WebSocket 后回到 ≤5s |

#### B2C 指标（v0.5 新增）
| 指标 | V1 目标 | 依据 / 注 |
|---|---|---|
| 自己练学员注册数（公测后 3 月）| ≥ 30 | 里欧海外 + 国内圈层种子 |
| 自己练学员 30 日留存 | ≥ 35% ⚠️ **未验证假设** | B2C 留存通常低于 B2B 学员（无教练督促）|
| **B2C 订阅转化率（试用 → 付费）**| **≥ 25%** ⚠️ **未验证假设** | 7-14 天免费试用后转化 |
| 模板完成率（一个周期完成）| ≥ 50% | 模板是否真的让学员能跟下来 |
| 自己练学员每周训练次数 | ≥ 3 | 同 B2B 学员基线 |
| B2C ARPU（月） | **TBD - V1 公测前定**（v0.7 议题 10 决议：等产品做出来再定价）| 定价待研究，详见 §10 H5 |

### 7.3 V1 关键转化指标（免费期结束后评估）

| 指标 | V1 目标 | 风险 |
|---|---|---|
| 教练免费期转付费率 | ≥ 50% | H3 待验证假设，详见 §10 |
| 教练月流失率（付费后） | ≤ 10% | 切换成本沉没 |

### 7.4 三档区间响应（明确每档对应动作）

| 教练免费期转付费率 | 触发动作 |
|---|---|
| ≥ 50% | 维持现行定价 + 免费期策略，进入下一阶段增长 |
| 25%-50% | **重审**——访谈未付费教练理解原因，可能调整定价档位（更便宜入门档）或缩短免费期到 1 个月 |
| < 25% | **叫停 V1 商业化**，重审 P6（定价 + 免费期）和 P2（值不值得换）双假设 |

### 7.5 反向指标（哪些数据看到要叫停 V1）
- 教练周活率 < 50% → 没有形成"每周排计划"习惯，工作流闭环失败
- 学员 30 日留存 < 25% → "看到进步"价值不成立（H4 崩盘信号，强制前置 ADR 002）
- 任意单月有 ≥3 名教练主动卸载且反馈"还是用微信"→ P2 假设崩盘（不够好到值得换）

## 8. 依赖 / 约束

### 8.1 平台约束
- **iOS 17+**（覆盖 ~90% 在用 iPhone）
- **SwiftUI**（首选，UIKit 兜底）
- **Apple Developer 账号**：⚠️ 待确认是否已开通（个人 ¥688/年 / 公司 ¥1948/年——v0.3 团队是 3 人，未来可能需要公司账号）

### 8.2 后端约束
- **后端选型**：候选 **Supabase**（实时同步天然支持，B2B 体量起步友好）/ Firebase / 自建 Node + PostgreSQL
  - **决策标准**（v0.3 强化）：选项必须满足
    1. **国内存储 + 国内可访问**（PIPL 合规，详见 §8.7）→ 注意 Firebase 无中国 region，Supabase 自托管或国内云
    2. **海外节点可访问**（里欧的海外学员访问需求）
    3. 实时同步开箱（学员录入 → 教练端 ≤5s）
    4. 无需大量后端工程（3 人团队约束）
  - **触发新 ADR**（详见 §13.2 #4）
- **视频存储**：候选阿里云 OSS / 腾讯云 COS / 七牛（中国区域优先）+ 海外加速节点
- **推送通知**：APNs（详见 §5 P0 #14 事件清单）
- **实时同步**：WebSocket（首选）/ Firestore-style listen / polling 兜底——和后端选型同步决策

### 8.3 App Store 分发约束
- ⚠️ **App 分发策略待技术决策**（详见 §13.2 #5）：
  - **方案 A：单 binary + 角色切换**——共享代码、一次提审、ASO 描述需服务双角色
  - **方案 B：双 binary 双 listing**——清晰 ASO，但 2x 提审周期、2x 评论/崩溃跟踪
- **审核风险**：力量举内容无敏感分类，但 Apple 对运动健康类 app 有数据隐私要求
- **Sign-In with Apple**：Apple §4.8 强制要求——任何第三方 SSO 必须并列 Apple Sign-In。V1 默认手机号 + Apple Sign-In 双入口
- **支付**：教练订阅必须走 IAP（30% 抽成）；中国教练 B2B 用户对发票（fapiao）有需求，IAP 默认提供"购买凭证"非增值税发票
  - 30% 抽成对 15-25 元/学员/月定价的实际净收入：≈ 5-8 元/学员/月
  - **V1.5"企业版"走外部支付（对公转账）**仅适用于"企业批量采购"形态（明确不卖数字商品给终端用户），需 ADR 评估 Apple §3.1.1 边界，不得在 app 内直接引导用户外部支付——v0.3 明确这是合规红线

### 8.4 团队 / 时间约束（v0.5 重估含 AI coding 加速 + B2C 双模式）

- **团队**：3 人创始团队（详见 §2.5）
  - David：CEO + 技术负责人 + 唯一全职工程
  - 肖天宇：产品顾问 + 教练端获客
  - 里欧：产品顾问 + 学员端获客 + **欧美主流训练模板交付**（V1 学员端 critical path）
- **AI 辅助**：Claude Code 加持
  - Boilerplate / CRUD / 测试：5-20x
  - 模式重复 / 已知 pattern：3-8x
  - 新架构 / UX 迭代 / 算法正确性：1.5-3x
  - iOS 平台 debugging / 集成：1-2x
  - App Store 审核 / ICP / 真实用户反馈：**1x（不能加速）**
  - Realistic blended for first iOS app + 你这个 stack：**3-5x**
- **目标节奏**（v0.7 修订，AI coded + 7-stage lifecycle）：

> v0.7 用业内通用 7-stage lifecycle（详见 [[lifecycle-stages]]）替代 v0.6 的 2-stage（内测+公测），更精确反映 V1 → GA 的真实节奏。

| Stage | 时间窗 | 累计周数 | 用户规模 |
|---|---|---|---|
| Stage 2 Engineering Build | Week 0-12 | 12 周 | 2 内部教练 dogfood |
| Stage 3 Closed Alpha 闭门内测 | Week 12-18 | 6 周 | 5 教练 / 25-50 学员 |
| Stage 4 Closed Beta 闭门公测 | Week 18-26 | 8 周 | **24 教练 + 30 自己练 = ~210-360 active** |

**资源量基础**（详见 [[lifecycle-stages]] §2）：手头 24 教练 + 30 自己练 = ~210-360 active users 的 Stage 4 储备，已超大部分 SaaS 全 GA 用户量。

**Stage 4 gradual rollout** 防后端崩 + onboarding 经验积累——见 [[lifecycle-stages]] §3。

> **Phasing 含义**：内测 phase 1 = B2B（Week 0-9）；phase 2 = + B2C（Week 9-12）；公测 = 双模式齐发（Week 14+）。**B2C engineering 的 hard gate = 里欧模板交付**。

### 8.5 法务 / 合规约束
- **国内分发**：iOS App Store 中国区**强制要求 ICP 备案**（2023 末新规），软著（30-60 天）+ 备案需要**前置启动**（详见 §13.2 #11/#12）
- **隐私合规**：详见 §8.7
- **运动数据**：训练数据是否构成"健康数据"（HealthKit 范畴）需法律确认（影响是否走 HealthKit / 存储等级要求）
- **公司主体**：v0.3 团队是 3 人，可能需要在 V1 公测前注册公司主体（影响 Apple Developer 账号、收款、报税、纠纷处理）

### 8.6 无障碍（Accessibility）

**V1 最低要求**：
- VoiceOver：所有 P0 屏幕的核心控件标注（按钮、滑块、卡片）
- Dynamic Type：支持到 XXL
- 颜色对比：≥ WCAG AA（4.5:1 文本，3:1 大字号 / 图形）
- 触控目标：≥ 44×44pt（iOS HIG 强制）
- 不依赖颜色单一传达信息（如完成度的绿/红 + icon 双编码）

**V1 不强求**：完整 VoiceOver rotor 自定义、深色模式适配（V1.5）

### 8.7 隐私与数据处理（PIPL 适用）

**数据本地化**：
- 用户个人信息（手机号、视频、训练数据）默认存储在中国境内服务器（PIPL 合规）
- 海外学员（如里欧客户中的）需评估跨境传输方案——V1 阶段尽量做"海外可读，但数据存中国境内"的 CDN 架构

**数据生命周期**：
- 注册同意：用户同意隐私政策 + 用户协议（双勾选）
- 数据访问：用户可在 app 内查看本人所有训练数据 / 视频 / 反馈
- 数据删除：用户可在 app 内删除账号；删除流程 30 天内执行；账号删除后绑定的教练-学员关系解除
- 数据保留：账号注销后 30 天软删（可恢复），之后硬删
- 教练账号注销：30 个活跃学员被解绑通知，**学员保留对历史计划/反馈的只读权（教练姓名匿名化为"前教练"），未来计划/活跃绑定关系全部解除**；视频附件保留在学员侧，孤儿视频存储成本由平台兜（V1 阶段可控）

**视频 ACL**：
- 学员视频默认仅绑定的教练可见
- 学员可在 app 内单独删除某段视频（教练侧同步移除引用）
- V1 不做：学员设置"仅本人可见"模式（V2 评估）
- 教练 V2 团队功能上线时，视频访问权限需重新评估（不向同事自动可见）
- **首次视频上传时弹窗显式 consent**（"该视频仅你绑定的教练可见，是否继续？"）+ consent 记录入数据库供合规审计

**未成年人**：
- V1 注册流程要求年龄确认 ≥18
- 未成年学员的产品支持列入 V2（涉及监护人同意流程，复杂）

**敏感事件处理**：
- 教练学员关系解除中的争议、视频内容争议——V1 通过 app 内邮件 / 客服邮箱处理（V1 不做产品级争议解决流程）
- IAP 退款：走 Apple 标准退款渠道，平台仅提供退款政策说明 + 客服协助

### 8.8 离线行为与同步

**学员侧（核心场景：健身房弱网/无网）**：
- 训练数据录入：本地 SQLite 持久化，恢复网络后自动同步
- 视频上传：本地队列 + 断点续传（PUT with Range / 分片上传）
- 教练反馈接收：上一次缓存可见；新反馈需联网
- 冲突策略：训练记录 last-write-wins（学员是单写者）

**教练侧**：
- 学员状态面板 / 反馈队列：上一次缓存可见
- 反馈写入：本地缓存 + 联网后提交（无冲突，教练是单写者）

### 8.9 国际化与单位制

**V1 语言**：仅 zh-CN（简体中文）
**V1 单位**：仅公斤（kg）+ 厘米（cm）
**V1.5 评估**：zh-TW（里欧台湾用户）+ 港澳台力量举圈用户访问意愿；磅（lb）切换
**永不做**：除中文外的语种（产品定位是中文力量举垂直）

### 8.10 视频管线（独立列出，工程复杂度高 + lean 优化）

V1 视频管线最小集：
- 录制：AVFoundation 直接调相机，**默认 60s 最大 120s**（v0.7 议题 7 调整：之前 v0.6 是 90s）；角度由教练根据需求决定（无产品强制 default 角度）；每动作每组都有上传入口（不是 selective）

**v0.7.3 lean 优化（2026-04-27）—— MPS 转码月费降 50%**：
- **客户端转码 H.264**（现代 iPhone CPU 强，AVAssetExportSession 内置）—— 减少服务端转码量
- **服务端仅对"主项关键 set"二次转码 H.265**（节省存储 + CDN 流量）
- **辅助项视频不转码**，仅做缩略图（OSS 标准存储 + 客户端按需 stream）
- **缩略图客户端生成**（不走 MPS）—— 用 AVAssetImageGenerator
- **限制视频码率 1Mbps**（H.265 高效，720p 1Mbps 够清晰）
- 预估优化后 MPS 月费：**Stage 4 ¥500 / Stage 5 ¥1500 / Stage 6 ¥3500**（vs 优化前 ¥1700/3500/7000，省 50%+）
- 转码：**服务端转码到 H.265**——客户端转码致老设备发热，服务端用阿里云 MPS（Media Processing Service）或 ffmpeg 自管。新增成本：阿里云 MPS ≈ 0.05 元/分钟视频，月 100 教练 × 30 学员 × 5 训练 × 3 视频 × 0.75 分钟 = 33,750 分钟/月 = ~1700 元/月。R6 储存成本表已加。
- 上传：URLSessionUploadTask 分片 + 断点续传（前端）+ 分片合并校验（后端）
- 播放：AVPlayer + 标准控件 + 倍速（0.5x/1x/1.5x/2x）
- 缩略图：服务端生成，客户端按需下载
- 元数据叠加（教练播放页"张三 · 周三 · 深蹲 · 第 4 组 · 100kg×5 · RPE 8"）：纯 SwiftUI overlay，不烧到视频

**预估单工程师工程量**：4-6 周（首次 iOS 视频管线学习成本占 30%+）；3 人团队中里欧若有视频开发经验可平行启动

| 风险 | 缓解 |

### 9.2 P1 中风险（影响节奏 / 规模）
