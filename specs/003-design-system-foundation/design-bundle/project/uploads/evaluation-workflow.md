## 0. 设计哲学

> **教练是计划的 owner，学员是执行者 + 反馈者**。
> 评估期把"好教练隐性流程"显性化——MeetPR 用产品强制让教练评估，对比微信"我看一下你视频"的草率。
> v1 决议来自 office hours 2026-04-26 Gap #1 + Gap #3 拷问（共 13 项决议）。

## 0.1 v1 → v1.1 update（领域会议议题 6 PR 重塑）

议题 6 决议影响 evaluation-workflow：

- **1RM 锁定不动**：评估期内教练填评估总结时，**不会** update 学员 1RM 字段
- **e1RM 每天自动 update**：每次训练完成后系统按 RPE-based 公式自动 recompute；评估期内学员的训练数据进 e1RM 历史
- **PR 推送规则**：e1RM 突破历史最高 → 自动推送学员；教练侧不被 PR 推送（教练打开学员曲线能看到增长即可）
- 详见 [[prd|PRD v0.7]] §5 P0 #16 + [[data-model]] e1RM_history 表

## 1. 完整 funnel 概览

```
[1] 教练发邀请码（Personal / 一次性 / 限时）
        ↓
[2] 学员扫码 → 完成 onboarding
        ↓
[3] 学员发"绑定请求"→ 进教练"接收队列"
        ↓ 显式 + 48h 教练再推 + 7 天 expired
[4] 教练在接收队列看摘要 → 决策"接收 / 拒绝"
        ↓
    ┌───┴───┐
[拒绝]   [接收]
  ↓         ↓ 弹模态 2 选 1
silent  ┌──────┴──────┐
中性   "进评估期"  "跳过评估期（熟人）"
        ↓             ↓
    [5] 7 天评估期      → [9] 首份正式计划
        ↓
    ┌───┼───┐
[期内]: 看资料 + 发适应周 + 留言
不能: 发正式 4 周计划
        ↓
    7 天到 OR 教练提前点"评估完成"
        ↓
[6] 教练填评估总结（3 自由文本字段，8-12 分钟）
        ↓ 首次保存自动推送学员
[7] 学员收到评估摘要 + 一键展开看全文
        ↓ 软推荐
[8] 教练弹"立即排第一份计划 / 稍后"
        ↓
[9] 首份正式计划发布
```

## 2. 邀请码体系（3 类 code）

> office hours Gap #3 V1 默认升级——支持 Personal + 一次性 + 限时 三种 code。

### 2.1 Code 类型

| 类型 | 用途 | Lifecycle |
|---|---|---|
| **Personal 永久 code** | 教练随身固定码（朋友圈 / 名片）| 永久有效；可手动 revoke 后重新生成 |
| **一次性 code** | 特定学员邀请（"小明，扫这个码"）| 用 1 次后自动失效 |
| **限时 code** | 推广 / 馆内活动 | 设过期时间（如 7/30/自定义天）；到期失效 |

每教练 default = 1 个 Personal 永久 code。一次性 + 限时 code 按需生成，无数量限制。

### 2.2 Code 生成 UX（教练侧）

```
┌─────────────────────────────────────┐
│ 我的邀请码                            │
│                                     │
│ ┌── Personal 永久码 ────────────┐  │
│ │  XYZ-ABC-123                   │  │
│ │  扫码次数: 23                   │  │
│ │  [复制] [生成新码]              │  │
│ └────────────────────────────────┘  │
│                                     │
│ ┌── 一次性码 + 限时码 ──────────┐   │
│ │ [+ 生成一次性码]                │   │
│ │ [+ 生成限时码]                  │   │
│ │                                │   │
│ │ 现有码:                         │   │
│ │ · 一次性 / 给小明 / 待用         │   │
│ │ · 限时 / 馆活动周 / 6 天后过期  │   │
│ └────────────────────────────────┘   │
└─────────────────────────────────────┘
```

### 2.3 数据模型

```sql
invite_codes:
  - id: UUID
  - coach_id: UUID FK
  - code: TEXT (10-char alphanumeric, indexed unique)
  - type: enum('personal_permanent', 'single_use', 'time_limited')
  - max_uses: INT (NULL for personal/time_limited; 1 for single_use)
  - used_count: INT (default 0)
  - expires_at: TIMESTAMP (NULL for personal_permanent/single_use)
  - revoked_at: TIMESTAMP (nullable, set if coach manually revoked)
  - label: TEXT (nullable, 教练自填如"给小明")
  - created_at
```

### 2.4 V1 不做（明确）
- ❌ Spam 防护（30 天限 1 次绑定请求）—— office hours 2026-04-26 决定移除，silent 拒绝本身已是阻力
- ❌ Code 数量上限
- ❌ Code 数据分析（"哪个码最有效"）—— V1.5 候选

### 3.2 接收队列摘要字段（v1 spec）

每张请求卡片摘要展示 9 项：
1. 姓名 / 性别 / 年龄 / 体重
2. 训练年限
3. 三大项 1RM
4. 想增强肌群
5. 训练环境（gym tier）
6. 备赛 / 比赛日期（如有）
7. 备注（学员"想对教练说"）
8. 上传资料计数（"3 视频 + 1 计划"）
9. 已等待时长

### 3.3 [接收] 按钮 — 弹模态 2 选 1

```
教练点 [接收] →
┌─────────────────────────────┐
│ 接收 张三 进入：               │
│                              │
│  [● 进入 7 天评估期]          │
│   推荐：陌生 / 不熟悉的学员    │
│                              │
│  [○ 跳过评估期（熟人）]        │
│   适合：已带过的 / 朋友介绍    │
│   原因 (可选): [_________]    │
│                              │
│ [取消]            [确认接收]  │
└─────────────────────────────┘
```

- 选"进评估期" → 创建 evaluation_period 记录 + 学员侧推送"教练已接收，评估期 7 天开始"+ 教练侧训练计划锁定（不能发正式 4 周）
- 选"跳过评估期" → 不创建 evaluation_period + 学员侧推送"教练已接收"+ 教练直接进入排首份计划流程

### 3.4 [拒绝] 按钮 — silent 中性

```
教练点 [拒绝] →
学员侧推送（中性 silent）：
"教练当前不接收新学员。请输入新邀请码或继续浏览自己练模式。"

教练侧无填原因要求。bind_request status = rejected。
```

### 3.5 学员侧"待接收"状态

```
学员扫码注册后立即看到：

┌─────────────────────────────────────┐
│ 已发送绑定请求                       │
│ 等待教练 张三 接收                   │
│                                     │
│ 已等待: 2 小时 14 分                 │
│ 教练通常在 24h 内响应                 │
│                                     │
│ [取消请求]                           │
└─────────────────────────────────────┘

教练 48h 未响应 → 学员推送"教练尚未响应"+ 教练再推 1 次
教练 7 天未响应 → 自动 expired + 学员推送"请求过期，可重新发送或换教练"
```

### 3.6 数据模型

```sql
bind_requests:
  - id: UUID
  - student_id: UUID FK
  - coach_id: UUID FK
  - invite_code_id: UUID FK
  - status: enum('pending', 'accepted', 'rejected', 'expired', 'cancelled')
  - submitted_at: TIMESTAMP
  - responded_at: TIMESTAMP (nullable)
  - expired_at: TIMESTAMP (nullable, set if 7 天 auto-clear)
  - skip_evaluation: BOOLEAN (true = 教练接收时勾选"跳过评估期")
  - skip_reason: TEXT (nullable, 教练填的可选原因)
  - rejection_silent: BOOLEAN (true)  -- v1 always silent rejection
```

## 4. 评估期（7 天硬框架）

### 4.1 进入评估期的条件

教练在接收 moment 选"进入 7 天评估期"。系统创建 evaluation_period 记录。

### 4.2 期内规则

| 类别 | 教练能做 | 教练不能做 |
|---|---|---|
| 信息查看 | 学员上传的视频 / 训练计划 / onboarding 数据 | — |
| 计划编排 | **发"适应周"训练**（1 周轻量计划，技术为主，不押重量）| **不能发正式 4 周计划** |
| 沟通 | 给学员留言（一次性的反馈，不是结构化总结）| — |
| 视频处理 | AVPlayer + 倍速看视频 | 不能 timestamp 评论（V1.5 评估）/ 不能画线标注（V2）|
| 总结 | 随时进入"评估总结"页面填写 | — |
| 终止 | 提前点"评估完成"结束评估期 | — |
| 跳过（事后）| 决定该学员不带 → "解除绑定"按钮 | — |

### 4.3 期内学员看到什么

```
学员评估期主页：

┌─────────────────────────────────────┐
│ 评估进行中                           │
│ 教练 张三 正在评估你                  │
│                                     │
│ 评估期还剩: 4 天 13 小时              │
│ ████████░░░░░░░░░ (55%)             │
│                                     │
│ 教练已查看资料: 3/4 视频 + 1 计划   │
│                                     │
│ ┌── 教练留言 ────────────────────┐  │
│ │ 张三, 我看了你的深蹲视频, 注意你 │  │
│ │ 触底节奏太快, 评估总结里详谈     │  │
│ │ — 教练张三 · 2 小时前            │  │
│ └────────────────────────────────┘  │
│                                     │
│ ┌── 适应周训练 (本周) ────────────┐ │
│ │ 周一: 深蹲 4×5 @70% 1RM         │ │
│ │ 周三: 卧推 4×5 @70%             │ │
│ │ 周五: 硬拉 4×5 @65%             │ │
│ │ [开始训练]                      │ │
│ └────────────────────────────────┘  │
└─────────────────────────────────────┘
```

### 4.4 超期处理（36h 催 1 次，无"换教练"）

- 评估期到 7×24h 整点：教练侧推送"该学员评估期已结束，请尽快交付总结"
- 36h 后未交付：教练侧再推 1 次"已超期 36h，请处理"
- **学员侧不显示"换教练"按钮**（marketplace 成熟前没有 marketplace 实现路径）
- 学员看到的状态：仍然是"评估进行中"，无负面提示
- V3 marketplace 上线后：评估期严格保护学员（"已超期 X 天" + [换教练]）

### 4.5 数据模型

```sql
evaluation_periods:
  - id: UUID
  - student_id: UUID FK
  - coach_id: UUID FK
  - bind_request_id: UUID FK
  - started_at: TIMESTAMP
  - expected_end_at: TIMESTAMP (started_at + 7d)
  - completed_at: TIMESTAMP (nullable, 教练 OR 系统标记完成)
  - completion_type: enum('coach_completed', 'auto_completed', 'overdue', 'cancelled')
  - overdue_first_push_at: TIMESTAMP (nullable)
  - overdue_second_push_at: TIMESTAMP (nullable, +36h)
```

## 5. 评估总结（3 字段简化模板）

> office hours Gap #1 v3 → v3.1 简化决议：从 9 字段重模板 → 3 字段自由文本。

### 5.1 模板字段

| 字段 | 类型 | 必填 | 学员可见 | 用途 |
|---|---|---|---|---|
| 整体评估 | 自由文本 | ✓ | ✓ | 教练对学员能力的整体观察 |
| 训练规划 | 自由文本 | ✓ | ✓ | 接下来的训练方向 / 周期化思路 / 重点 |
| 给学员的话 | 自由文本 | 选填 | ✓ | 鼓励 / 期望管理 / 第一阶段目标 |

无字段对学员隐藏。无星评 / 无 enum / 无水平等级。

```
│ │ [_________________________]    │ │
│ │ [_________________________]    │ │
│ └────────────────────────────────┘ │
│                                     │
│ ┌── 训练规划 (必填) ──────────────┐ │
│ │ [_________________________]    │ │
│ │ [_________________________]    │ │
│ │ [_________________________]    │ │
│ └────────────────────────────────┘ │
│                                     │
│ ┌── 给学员的话 (选填) ────────────┐ │
│ │ [_________________________]    │ │
│ │ [_________________________]    │ │

│                                     │
│ ☐ 通知学员 (首次保存默认勾选)        │
│                                     │
```

```
│ │ [展开看完整]                    │  │

│                                     │
│ ┌── 教练给你的话 ────────────────┐  │
│ │ "你深蹲技术稳定，硬拉触地节奏需  │  │
│ │  调整。第 1 阶段我们专注修复..."│  │
│ │ [展开看完整]                    │  │
│ └────────────────────────────────┘  │
│                                     │
│ [展开看完整评估]                     │
│                                     │
│ ── 下一步 ──                         │
│ 教练正在为你排第一份正式计划，预计   │

└─────────────────────────────────────┘
```

摘要 = 训练规划前 1-2 句 + 给学员的话前 1-2 句。完整展开 = 3 字段全文。

### 5.4 后续修改推送规则

- **首次保存** = 自动推送学员（"教练完成你的评估"）
- **后续修改** = 默认 silent + 教练保存时可勾选"通知学员"

教练保存评估总结时的 UX：
```
[保存草稿]   [保存 + ☐ 通知学员]
              ↑ 首次保存默认勾选；
                后续修改默认不勾选
```

### 5.5 评估总结 = 学员信息卡片永久内容

教练随时可调整评估总结。评估总结存储在学员档案，不是临时文件。

学员"我的资料"和教练"学员详情页"都有"评估总结"入口可查看 + 编辑（教练侧可编辑，学员侧只读）。

### 5.6 数据模型

```sql
student_evaluations:
  - id: UUID
  - student_id: UUID FK
  - coach_id: UUID FK
  - evaluation_period_id: UUID FK (nullable, 跳过评估期则为 NULL)
  - overall_assessment: TEXT (整体评估)
  - training_plan: TEXT (训练规划)
  - words_to_student: TEXT (给学员的话, nullable)
  - first_saved_at: TIMESTAMP
  - last_updated_at: TIMESTAMP
  - is_active: BOOLEAN (true = 当前 active 版本)

student_evaluation_versions:
  - id: UUID
  - evaluation_id: UUID FK
  - overall_assessment: TEXT (snapshot)
  - training_plan: TEXT
  - words_to_student: TEXT
  - notified_student: BOOLEAN (本次保存时是否推送学员)
  - saved_at: TIMESTAMP
```

## 6. 评估总结 → 首份正式计划（软推荐）

### 6.1 教练端 UX

```
教练点"完成 + 通知学员"保存评估总结后 →

┌─────────────────────────────┐
│ ✓ 评估完成                   │
│ 学员张三已收到通知。          │
│                              │
│ 要不要立即为他排第一份正式    │
│ 计划？                        │
│                              │
│ [立即排]  [稍后]              │
└─────────────────────────────┘
```

- 点"立即排" → 跳到[[coach-planning|coach-planning v4]] 流程，预填该学员的 1RM + 训练日 + 训练环境
- 点"稍后" → 退出。教练自己什么时候有空再去排

### 6.2 学员侧"等待首份计划"状态

学员看完评估总结后看到：
```
"教练正在为你排第一份正式计划，预计 24 小时内发布。"
```

教练发布后学员收到推送 → 进入正式训练。

## 7. office hours 2026-04-26 决议清单

8 项 Gap #1 + 5 项 Gap #3（与本 spec 直接相关）共 13 项决议汇总：

| # | 决议 |
|---|---|
| 1.1 | 评估期独立产品概念 + 熟人可跳过 |
| 1.2 | 7 天硬截止 + 期内可发适应周不可发正式 4 周 |
| 1.3 | 评估总结 = 3 自由文本字段 |
| 1.4 | 视频评估 = 仅看 + 总结里写文字评 |
| 1.5 | 超期处理 = 36h 催 1 次 + 无换教练按钮（marketplace 前）|
