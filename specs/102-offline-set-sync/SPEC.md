# 102 — 打勾先变绿：组记录本机排队、后台同步

- **状态**: Ready（2026-11-05 /grill 共识「确认」；同日 David 改拍：组记录同步只在长按完成后露面、奖励前同步完，其余静默，超时才报失败，见 §2、§4；同日屏幕稿「定稿」，结构转写在「屏幕稿」节）
- **来源**: 学员反馈「网络不好的时候点完成 ✅ 要等很久」（2026-11-05 iOS 真机截图：坐姿哑铃推举第 2 组转圈、「全部按计划完成」变灰）。
- **范围**: 学员端今日训练卡，iOS（`MeetPR` 仓 `release/1.0`）与安卓 RN（`meetpr-rn` 仓 `main`）同批派卡、同批验收；两仓同目录镜像本文件。
- **级别 / 节奏**: T2 / P1。纯客户端，无后端、无数据模型改动（若实装中发现必须改后端，停下回报，不自行扩范围）。
- **相关**: spec 101（训练视频零丢失）同样改「完成今日训练」的流程：长按后先出奖励，奖励页关闭后显示视频上传进度。本 spec 的组记录同步插在长按与奖励之间，两边按 §2 共用一个完成流程。

## 北极星

**点了就算数。** 学员点 ✅ 的那一刻就是完成，不等网络。记录先存在手机里，有网就传，传不上就一直重试，不丢，也不让学员重点。训练过程中不打扰学员，只在完成今日训练时统一交代。

## 术语

**待同步（pending sync）**: 学员已经在手机上记下、但服务器还没确认收到的组记录（含勾选、取消勾选、改数、加组、删自加组、标未完成）。待同步的记录在界面上就当作已经生效。

## 现状（已核实，iOS `origin/release/1.0` 09eef51d / RN `origin/main` 6550369 / 后端 `origin/staging`）

- iOS：`TodayWorkoutViewModel.saveAccessoryRow` / `persist` 先 `await` 服务器返回才更新界面。等待期间 `accessorySavingIDs` 非空，**同一动作的其他组和「全部按计划完成」一起被禁用**。失败会把行回滚成原值。
- RN：`setsRepository.upsert`（`src/api/domains/sets.ts`）同样 `await`，30 秒超时。
- 后端 `POST /sets/log` 是按 `(student_id, plan_exercise_id, set_index)` 的**幂等 upsert**（`src/handlers/sets-log.ts`），重发同一组不会记成两条，后发的覆盖先发的。后端不拒绝往已完成的那天写组。是客户端的 `FlexibleTrainingDay.canWrite` 在完成后挡住写入。
- 「完成今日训练」走 `POST /plans/days/:dayId/complete`，入口是「长按 · 完成今日训练」。spec 101 已定：有视频未送达时，长按后奖励页立即出，奖励页关闭后显示「视频上传中」卡，全部送达后才调完成接口。
- 视频要挂到组上，需要组的服务端 id（iOS `ensureLoggedSetID`、RN `video-upload/manager.ts` 都会先补写一次组）。

## 变更

### 1. 打勾立即生效（两端）
1. **范围覆盖主项、主项变式、辅助项和学员自加，所有组的记录入口都算**：
   - 主项 / 主项变式：录入页的「完成本组」「未完成 / 失败」（iOS `SetEntrySheet.save` → `commitSet`，现在要等服务器成功才关页）。
   - 辅助项 / 不定重量 / 学员自加：卡内行的 ✅、取消勾选、改重量/次数/RPE、「加一组」、删自加组、「全部按计划完成」。

   以上操作一律让界面**立即**更新（录入页立即关闭），休息倒计时立即开始，不出现转圈。
2. 任何一组在同步中，**都不禁用**同一动作的其他组和「全部按计划完成」。
3. 操作写进本机的同步队列（落盘，杀 app、重启手机不丢），后台按点的顺序依次发给服务器。同一组连续改多次，以最后一次为准（可以合并，也可以按序全发，后端是幂等 upsert）。
4. 发送失败（断网、超时、5xx）自动重试，退避节奏实装方定，有网络恢复信号时立即重试。**不回滚界面**，不弹错误。
5. 服务器明确拒绝且重试也没用的（4xx，除下面 §3 的情况）：这一条停止自动重试，记为「没传上」，保留在队列里，等 §2 第 4 条的「重试」。不删除，不回滚。

### 2. 完成今日训练：先同步组记录，再出奖励（两端，David 改拍）
1. **长按前**：不显示任何组记录状态，按钮与现在一样。
2. **长按之后、奖励之前**：若这天还有待同步的组，先把它们立即发出（插队，不等退避）。按钮原位显示「正在同步训练记录…」，不弹窗（稿 ①）。队列本来就空则跳过这一步，直接出奖励。
3. **同步完成** → 照常立即出奖励页。之后按 spec 101 走：有视频未送达就显示「视频上传中」卡、等送达后调完成接口；没有视频就直接调完成接口。
4. **超时才反馈失败**：长按后 **20 秒**组记录仍没同步完（或期间遇到不可重试的 4xx），按钮位置换成失败态（稿 ②）：「训练记录还没传上去」+ 说明「记录都存在手机里，不会丢。网络好一点再试。」+ 按钮「重试」。**不出奖励页，不调完成接口**。点「重试」回到第 2 条重新计时。后台照常继续自动重试；学员离开再回来时按钮恢复为「长按 · 完成今日训练」。
5. **完成接口的调用条件**：这天的组全部同步完，**并且**视频全部送达（101）。两个 spec 共用同一个「完成闸门」，不能各写一个；闸门要落盘，杀进程后能恢复。
6. 奖励页的数据（破 PR 等）用手机上已有的记录计算，不等服务器。
7. 待同步的组还没拿到服务端 id 时，学员点组号拍视频照常可以拍。视频进入 101 的上传流程，等这一组同步完拿到 id 再挂上去。不允许出现「先联网再拍」。

### 3. 教练改了计划（两端，David 拍 3A）
同步时服务器表示这条组记录对应的计划动作已经不存在（教练删了或换了动作）：把这一组按**自加动作**（spec 092）记到这一天，动作用原来的 `exercise_id`，组的数据原样保留。不丢，不提示学员，教练能看到。

### 4. 其余一律静默（两端，David 改拍，取代原 4A 顶部条）
1. 组记录的同步**只**在长按完成后的那几秒露面（§2 第 2、4 条）。训练过程中、长按前、奖励页之后都不显示任何组记录同步提醒：没有顶部条，组行不加标记，汇总区不加行，没有弹窗。
2. 「没传上」（§1.5）也不单独提示，只在长按后按 §2 第 4 条以失败态出现。
3. 具体位置、颜色、间距以「定稿」屏幕稿为准；失败色与 101 一致（橙色）。

### 5. 退出登录与换账号（两端，David 拍 2A）
1. 队列**按账号**存在本机。
2. 有待同步记录时点退出登录：弹窗「还有 {n} 组没上传」，两个按钮「先上传再退出」（显示进度，传完自动退出；传不完可以取消）和「直接退出」。
3. 选「直接退出」：队列不删，同一账号下次在这台手机上登录时自动接着传。换别的账号登录时不发、不显示上一个账号的队列。
4. 只有删掉 app 才会真的丢。换手机时没传的记录只在旧手机上，旧手机有网打开一次就会传上去。

### 6. 刷新与冷启动（两端）
1. 下拉刷新、切 tab 回来、冷启动拉到的服务器数据，要叠加本机的待同步记录再显示。**不允许**刷新后已勾的组变回没勾。
2. 冷启动有队列时立即开始同步。

## 屏幕稿（2026-11-05 David「定稿」）

画布：https://claude.ai/artifact/XzbjkhWw3KPaSwhDNsCasJ 。稿只管布局、层级与文案；颜色、字号、圆角取各端 DesignSystem 现有 token，深浅色两套都要有。失败色与 101 一致（橙色）。

- **① 长按后 · 正在同步训练记录**：训练页做完的动作一列不变 → 底部吸附区原「长按 · 完成今日训练」按钮位置，换成同尺寸的不可点状态条：转圈图标 +「正在同步训练记录…」（品牌金字，按钮底色变暗）。上方无汇总行，下方无小字。同步完直接进奖励页。
- **② 20 秒没传完 · 失败态**：同一位置自上而下 = 橙色提示块（警告三角图标 + 加粗「训练记录还没传上去」，下一行缩进说明「记录都存在手机里，不会丢。网络好一点再试。」）→ 品牌金主按钮「重试」（与原长按按钮同尺寸，普通点按即可）。不出奖励页。
- **③ 退出登录弹窗**：居中卡片，标题加粗「还有 {n} 组没上传」，说明「直接退出也会保留，下次登录这个账号时接着传。」，下面三个通栏按钮用分隔线隔开：「先上传再退出」（品牌金加粗，首选）/「直接退出」/「取消」。优先复用各端现有确认弹窗组件。
- 训练中、长按前、奖励后：**无任何组记录同步 UI**。

## 验收清单

1. 两端：开飞行模式，主项在录入页点「完成本组」→ 录入页立即关闭、该组变绿、休息倒计时开始；辅助项连点同一动作 4 组 ✅ → 每次点都立即变绿、休息倒计时立即开始，没有转圈，其他组和「全部按计划完成」都能点；训练过程中**没有**任何同步提醒。关飞行模式 → 自动同步，服务端能查到这 4 组，数据正确。
2. 两端：弱网（Network Link Conditioner / 模拟器限速，高延迟加丢包）下点 ✅ → 同上，立即生效。
3. 两端：断网打勾后杀 app，再断网冷启动 → 已勾的组仍是绿的；恢复网络后自动传上。
4. 两端：断网记完全部组 → 长按按钮及其上方**没有**任何组记录提示；弱网下长按 → 按钮显示「正在同步训练记录…」，同步完立即出奖励页；服务器先收到全部组、再收到完成。
5. 两端：断网长按 → 「正在同步训练记录…」持续 20 秒后变为失败态（「训练记录还没传上去」+ 说明 +「重试」），**不出**奖励页、**不调**完成接口；恢复网络后点「重试」→ 同步完立即出奖励页，当天组数据完整。离开再回来，按钮恢复为「长按 · 完成今日训练」。
6. 两端：同一组断网下先勾、再改重量、再取消勾选 → 恢复网络后服务器上是最后一次的状态。
7. 两端：断网打勾后，教练在网页把这个动作删掉 → 恢复网络后这几组作为自加动作出现在这一天，数据不丢。
8. 两端：后端对某条返回不可重试的 4xx（测试里注入）→ 训练中、长按前都不提示，界面不回滚；长按后立即进入失败态；点「重试」再次发送。
9. 两端：有待同步时退出登录 → 弹窗出现；选「直接退出」后用同一账号登回来 → 自动接着传；换另一个账号登录 → 看不到、也不会发上一个账号的记录。
10. 两端：待同步的组点组号拍视频 → 可以正常拍；联网后组先同步、视频随后挂到这一组上（与 101 一起验）。
11. 两端：当天有视频没送达时长按完成 → 组记录先同步、再出奖励、再按 101 等视频；完成接口只在组和视频都齐了之后调用一次（与 101 一起验）。
12. 两端：队列为空时长按 → 直接出奖励，不闪「正在同步训练记录…」。
13. **带历史的老用户升级后第一屏**：升级前已有的记录、已完成的天、正在传的视频，升级后显示不变，不重复，不丢；升级那一刻没有队列，行为与现在一致。
14. 两端：网络正常时，行为与现在一致（只是不再有转圈，长按后最多一瞬「正在同步训练记录…」），服务器数据与改动前同样操作的结果一致。
15. 简中、英文、繁体各看一遍新文案；深浅色各看一遍。
16. 两端单测全绿；iOS 在 `iPhone 17e`、安卓在模拟器亲验 1、3–9、12 条并截图对照屏幕稿。

## 测试 seam

- **同步队列**：抽一个与界面无关的队列（iOS StudentKit 内，RN `src/features/training/` 下），注入「发送函数」「时钟」「网络状态」「存储」。在这一层测：顺序发送、失败重试不回滚、同一组合并、4xx 停止并标记、「立即发送」插队、按账号隔离、落盘后重建队列。
- **叠加显示**：一个纯函数「服务器快照 + 待同步队列 → 界面行状态」，测刷新不回退、取消勾选、改数。
- **完成流程**：与 spec 101 共用的完成闸门 + 协调器，注入时钟。测：队列空 → 直接奖励；20 秒内同步完 → 先同步后奖励；超过 20 秒或遇 4xx → 失败态、不出奖励、不调完成；重试重新计时；完成接口只在「组全部同步 且 视频全部送达」后调用一次；杀进程后恢复。
- **计划动作被删**：在队列的发送层注入「计划动作不存在」的错误，断言改成按自加动作写入。
- 优先复用现有 seam：iOS `TodayWorkoutViewModel` 的 repository 注入、RN `setsRepository` 的 mock（`src/api/domains/__tests__/repositories.test.ts`、`src/features/training/__tests__/completion-entry.test.tsx`）。

## Out of Scope

- 长按完成之外的任何组记录同步提醒（顶部条、组行标记、汇总区、奖励后卡片、弹窗）。退出登录弹窗（§5）除外。
- 补记（spec 081 quick log）、身体状态填写（readiness）、聊天：本次不进队列，行为不变。
- 教练端（iOS 教练模式、plan-web）任何「学员有记录没同步」的提示。
- 后端改动、冲突合并规则改动（后端照旧是后写覆盖）。
- 完全离线使用：没网时首次打开 app、拉计划仍然需要网络；本 spec 只保证已经打开的今日训练里的操作不等网。
- 多台手机同时记同一天的冲突处理。
- 视频上传本身的可靠性（归 spec 101）。
