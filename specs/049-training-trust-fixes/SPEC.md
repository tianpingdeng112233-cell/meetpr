## 1. 完成状态判定断裂(报告 P0-1)——「练完了,app 不认账」

**实测**:3/3 组全 ✓ → 滑动完成 → 回顾提交,回到今日 tab 依然「继续 W1D6 · 硬拉」,四段进度条不满;同一天周视图绿点、月视图黄点。
**证据**:`DashboardView.swift:369-405` 存在 complete→「今日已完成 · 查看」分支,但 `progress.state` 从未到达 `.complete` —— 完成态没有单一事实源(TrainingDayProgress 从 logs 推导的判定链与「滑动完成」写入的状态不接)。

**修法**:
- 完成态单一事实源:`TrainingDayProgress` 的判定以「当日该计划日全部 prescribed sets 均有 completed log」为准;「滑动完成」动作本身不再是旁路状态,它只是最后一组的提交入口(若有未完成组则逐组补交)。判定函数收敛到一处,今日 tab / 周视图 / 月视图 / 日历点全部消费同一输出。
- **完成庆祝时刻**(走查建议顺手做):`progress.state` 首次达到 `.complete` 时,今日卡切换「今日已完成 · 查看」+ 一次性庆祝反馈(轻量:动效/触感,不新增依赖)——学员每天唯一的成就反馈。
- 回归保护:周/月日历点与今日卡对同一数据永远一致(单元测试锁三个消费点同源)。

## 2. 锁住「今天」(报告 P0-4 + P0-5)——写入只留给今天

**实测**:未来/过去日期的「记录此组」「滑动完成今日训练」全部可操作,手滑就把明天标成练完;点「开始今天训练」CTA 还会掉进上次浏览的旧日期。

**修法**:
- **未来日期 = 只读**:非今天的未来日,set 行与滑动完成一律禁用(视觉降级 + 不可交互),文案「未来的训练到那天再记」。
- **过去日期 = 默认只读 + 显式补录**:过去日进入只读态,顶部给「补录这一天」显式动作,点击后才进入可编辑(补录态有明显标识);防手滑同时保留真实补录需求(P0-4 的产品裁决)。
- **CTA 强制回今天**:「开始今天训练」无条件重置日历选中态到真实今天再进入(不吃上次浏览日期的残留)。
- 日期判定统一走设备本地日历(与 spec 045 会话日口径一致)。

## 3. 重量数字键盘(报告 P1-1)——最高频摩擦

**实测**:RPE 计划天天浮动重量,175→150 要点 10 下 ±,长按不连发。

**修法**:`SetEntrySheet` 的重量大数字可点击 → 弹数字键盘直接输入(decimalPad,校验 0-9999.99、0.25 步进容忍);**保留 ±2.5 按钮**(片重心智);次数/RPE 不改(转盘/步进已够快)。solo 的 `SoloSetEntrySheet` 已有直输,保持一致。

## 4. 比赛倒计时跨天不刷(报告编号:比赛倒计时项)

**实测**:跨午夜后倒计时天数不重算(走查跨午夜观察发现)。
**修法**:倒计时消费方订阅 day-change(`NSCalendarDayChanged` 通知 + 前台激活时重算);**solo 形态隐藏比赛元素**(比赛模式是 Pro 词汇,Free solo 不出现)。
