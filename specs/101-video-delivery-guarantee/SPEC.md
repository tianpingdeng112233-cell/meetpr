# 101 — 训练视频零丢失：送达后才完成 + 失败提醒

- **状态**: Ready（2026-11-05 /grill 共识「确认」；同日屏幕稿「定稿」，结构与文案转写在文末「屏幕稿」）
- **来源**: 学员反馈「有些视频被吞了」（2026-11-05 iOS 真机录屏：W1D5、W2D1 卧推第 1 组、W2D2 深蹲第 3 组回看无视频）。
- **范围**: 学员端，iOS（`MeetPR` 仓 `release/1.0`）与安卓 RN（`meetpr-rn` 仓 `main`）同批派卡、同批验收；两仓同目录镜像本文件。
- **级别 / 节奏**: T2 / P1。纯客户端，无后端、无数据模型改动（若实装中发现必须改后端，停下回报，不自行扩范围）。
- **前置**: 视频挂错组的竞态 P0（`docs/diagnose/set-video-lost-2026-11-05.md`，iOS 已在本地复现）**另走修复卡**，不在本 spec 内。iOS 卡叠在该修复分支（`diagnose/set-video-lost-20261105`）之上开工，避免同文件冲突；安卓不受影响，可直接从 `main` 开。

## 北极星（David 原话口径）

**视频千万不能丢——学员不可能重新练一组。** 任何状态、任何清理、任何失败路径都不允许出现「请重新录」。

## 术语

**视频送达**：某组的视频在服务端上传完成，并且已挂到这一组上。只有送达才算这条视频的事结束了。在此之前它只是「在传」或「没传上」。

## 现状（已核实，iOS `origin/release/1.0` 09eef51d / RN `origin/main` 6550369）

- 两端已有分片上传 + 断点续传 + 指数退避重试（iOS spec 069：background `URLSession`，每片 etag 落盘；RN `multipart.ts` / `retry-scheduler.ts`）。退避约 1/2/5/10/15 分钟，30 分钟时间盒。
- 失败通知：iOS `UploadFailureNotifier` 用 **provisional（静默进通知中心）** 授权、30 分钟后才发；RN `failure-notifier.ts` 用 `video-upload` 渠道、`AndroidImportance.LOW`。
- 失败态 UI：只在记录弹窗的视频附件区显示「上传失败 + 重试」。**已完成训练日回看（spec 096）与今日训练卡没有失败态**——传失败的组只是少一个播放图标。
- 「完成今日训练」不看视频状态，有视频没传完也能完成。
- 本机留存（spec 070）：iOS `RetainedVideoCleanupPolicy` 只清「已上传」的文件，没传上的不碰 ✅。**RN `localRetentionRemovals` 的 500MB 护栏会删除「已准备、未上传」的文件** ❌——违反北极星，本 spec 修。
- 相机直拍：iOS `CameraRecorderView` 在学员授权相册时另存一份到相册；RN 待实装方核实并写进 JOURNAL。

## 变更

### 1. 零丢失（两端）
1. 一条视频在**送达**之前，本机文件不得被任何清理删除（隔天清扫、500MB 护栏、冷启动、换包升级都算）。超过 500MB 时只清已送达的；全是未送达的就不清，宁可超限。
2. 没有「视频已丢失 / 请重新录」状态。所有失败都可重试。
3. 极端情况本机文件确实不在了（卸载重装、系统清理）：该组显示失败态，重试动作变为「从相册重新选这条视频」，选好后挂回原来那一组，走正常上传。

### 2. 完成今日训练前统一检查（两端）
1. **全部记完时（稿 C）**：若当天有任何一组视频**未送达**（在传、退避中、失败都算），「长按 · 完成今日训练」按钮上方出现一条汇总：「{x} 条视频没传上 · {y} 条正在传 · 立即重试」（只有在传、没有失败时只写「{y} 条视频正在传」且不带重试）；按钮下方一行小字「视频传完后才会真正完成，长按后可以先离开」。按钮仍可长按，不禁用。
2. **长按之后，奖励先出（David 拍板 A）**：长按完成后**立即**照常出奖励页（数据都在本机，不等上传）。此时**不调用**现有完成接口，只在本机记下「等视频送达后完成」。
3. **奖励页关闭后（稿 D）**：回到训练页，原长按按钮的位置换成一张不挡操作的卡：「视频上传中 {done}/{total}」+ 进度条 + 「传完会自动完成今日训练，可以先离开，完成后会通知你。」同时立即重试所有失败 / 退避中的视频（插队，不等退避）。学员可以离开页面或离开 app。
4. 全部送达后**自动调用现有完成接口**（语义不变），训练页切到已完成态，并发通知「今日训练已完成，{n} 条视频已送达」。
5. 自长按起 **30 分钟**仍未全部送达：发通知「还有 {n} 条视频没传上，点击重试」；点通知 → 进 app 到今日训练并再次全部重试。保持「等视频送达后完成」，不回退成未完成。
6. 当天没有视频或全部已送达：行为与现在完全一样（长按 → 完成接口 → 奖励页）。
7. 「撤销完成」现有行为不变；等待送达期间学员若改了某组记录，按现有记录逻辑处理，送达后的自动完成以当时的记录为准。

**安卓差异（David 拍板 A）**：vivo 等机型会冻结后台进程并删定时器，且不引导学员开高耗电权限。安卓在后台能传就传；传不完则在学员下次打开 app 时自动接着传、传完自动完成；第 4、5 条的通知「尽量发」——后台被冻结时发不出不算缺陷。iOS 必须完整做（background session 唤醒后调完成接口 + 本地通知）。

### 3. 训练中失败当场可见（两端）
「失败」= 某组视频上传第一次失败（含正在退避重试）。**第一次失败就显示**，不等 30 分钟；后台照常自动重试，送达后失败态自动消失。重点在**训练进行中**把问题解决，回看页只兜历史。
1. **训练页顶部条（稿 A）**：周进度下方、做完的动作上方一条：失败图标 +「{n} 条视频没传上，正在自动重试」+ 右侧「立即重试」，点「立即重试」全部插队重试。没有失败时不出现。
2. **做完的动作行（稿 A/C）**：该动作有失败视频时，在「已完成 · {n} 组」左侧加失败图标。展开后失败组的行尾显示失败图标（替代播放图标的位置）。正在做的动作的组表同理。
3. **录入页（稿 B）**：沿用现有视频区与「上传失败 · 重试」，**只改布局**：「上传失败」文字 +「重试」「更换」「删除」三个按钮放在同一行（窄屏允许按钮只留图标，命中区 ≥ 44pt/dp）。保存这一组不等视频传完。
4. **已完成训练日回看（096，次要）**：失败组行尾显示失败图标与「没传上」，日卡上方一条「{n} 条视频没传上 · 重试」。主要覆盖本 spec 上线前已完成、视频没送达的历史训练日。
5. 正在正常上传、还没失败的视频：训练中不单独提醒（保持 069「无感」口径），只在全部记完时（第 2.1 条）统一体现。

### 4. 通知（两端）
1. iOS：视频上传相关通知从 provisional 改为正常横幅提醒，复用推送已有的通知授权；没有授权时请求一次正常授权；被拒则只靠页面失败态。
2. 安卓：`video-upload` 渠道重要性从 LOW 提到 DEFAULT（有横幅/声音按系统默认）。
3. 原 069 的「网络失败 30 分钟后冒头 / 确定性失败立即冒头」规则保留，文案统一为「有 N 条训练视频没传上，点击重试」。同一时刻只保留一条聚合通知，不逐条轰炸。

## 文案（简中 / English；繁体走现有生成流程）

| 用途 | 简中 | English |
|---|---|---|
| 完成前进度 | 视频上传中 {done}/{total} | Uploading videos {done}/{total} |

| 自动完成通知 | 今日训练已完成，{n} 条视频已送达 | Workout complete. {n} videos delivered. |

| 本机文件不在时的重试 | 从相册重新选这条视频 | Pick this video again from Photos |

## 屏幕稿（2026-11-05 David「定稿」）

画布：https://claude.ai/artifact/G9WZsVKcf8STMZfeTBbarn 。稿只管布局、层级与文案；颜色、字号、圆角取各端 DesignSystem 现有 token，深浅色两套都要有。失败统一用橙色（与品牌金在亮度上拉开），不用红绿区分。

- **A 训练中 · 一组视频没传上**：自上而下 = 周标题行 → 失败顶部条（失败图标、「1 条视频没传上，正在自动重试」、右侧「立即重试」）→ 做完的动作行（绿色对勾、动作名、橙色失败图标、「已完成 · 4 组 ›」）→ hero 卡（不变）→ 正在做的动作组表（不变）→ 休息条（不变）→ tab 栏。
- **B 录入页 · 当场重试**：现有录入页（参照 David 安卓截图：RPE 卡 → 视频播放器）不变；播放器下方一行 =「上传失败」(橙/红字，左对齐) + 「重试」「更换」「删除」三个描边按钮，右对齐同一行；原「更换 / 删除」单独一行取消。底部「完成本组」「未完成 / 失败」不变。
- **C 全部记完 · 完成前统一提醒**：做完的动作一列（有失败的行带橙色图标）→ 底部吸附区：汇总条（失败图标、「1 条视频没传上 · 1 条正在传」、右侧「立即重试」）→「长按 · 完成今日训练」→ 小字「视频传完后才会真正完成，长按后可以先离开」→ tab 栏。
- **（C → 奖励页）**：长按后奖励页照常立即出，奖励页本身不改。
- **D 奖励页结束后 · 等视频送达**：做完的动作一列 → 底部吸附区（原长按按钮位置）一张卡：上传图标 +「视频上传中 2/3」、金色进度条、「传完会自动完成今日训练，可以先离开，完成后会通知你。」→ tab 栏。不弹窗、不挡操作。全部送达后此卡消失，页面切到已完成态。
- **E 三条通知**：①「今日训练已完成，3 条视频已送达」（全部送达自动完成）；②「还有 1 条视频没传上，点击重试」（长按 30 分钟后仍未送达）；③「有 2 条训练视频没传上，点击重试」（平时失败：网络失败 30 分钟 / 确定性失败立即）。点任意一条 → 进今日训练（或该训练日回看）并立即全部重试；同一时刻只留一条聚合通知。
- **次要 · 历史训练日回看**：已完成态日卡顶部「1 条视频没传上 · 重试」；失败组行尾「没传上」+ 橙色图标替代播放图标。
- **次要 · 本机文件不在**：底部弹层 = 组信息小字（如「竞技卧推 · 第 1 组 · 90 kg × 1 · RPE 8」）→ 失败图标 +「这条视频没传上」→ 说明「手机里找不到这条视频的文件了。录像时它也存了一份到相册，选出来就能挂回这一组。」→ 金色主按钮「从相册重新选这条视频」→ 次按钮「先不管」。

## 验收清单

1. 两端：当天 3 组带视频，全部记完时断网 → 长按按钮上方出现汇总条；长按 → 奖励页立即出现；关闭奖励页 → 训练页底部是「视频上传中 0/3」卡，今日训练**未**调用完成接口；恢复网络后自动送达、自动完成、卡片消失；iOS 收到完成通知。
2. iOS：长按完成并看完奖励页后立即杀 app，网络正常 → 视频在后台送达、完成接口被调用、收到完成通知（真机 HITL，模拟器只验前台路径）。安卓：同样操作 → 下次打开自动接着传并完成。
3. 两端：长按后保持断网 30 分钟（测试注入时钟）→ 收到「还有 N 条视频没传上，点击重试」；点通知进今日训练并触发重试；仍是「等送达」状态。
4. 两端：训练中某组视频第一次上传失败 → 训练页顶部条与做完动作行的失败图标立即出现；点「立即重试」插队重试；恢复网络后送达，顶部条与图标消失。
5. 两端：录入页视频失败时，「上传失败」与「重试」「更换」「删除」在同一行；三按钮均可用；最小屏宽不截断、命中区达标。
6. 两端：已完成训练日里有未送达的视频 → 回看页失败条与组行「没传上」出现；重试送达后变回播放图标。
7. 两端：当天无视频或全部已送达 → 长按 → 完成接口 → 奖励页，与现在完全一致。
8. 两端：留存清扫决策表——未送达文件在隔天、超 500MB、冷启动三种情况下都不被删除；RN 现有「已准备未上传被护栏删除」用例改为先红后绿。
9. 两端：本机文件被删后（测试里直接删文件）该组显示失败态，弹层按稿「本机文件不在」，选相册视频后挂回原组并送达。
10. **带历史的老用户升级后第一屏**：升级前已有「在传 / 失败」视频的老数据，升级后不丢、按新口径显示失败态并可重试；已送达的视频与回看不受影响；升级前已完成的训练日不会被重新要求「等送达」。
11. 两端：iOS 通知为正常横幅（非静默）；安卓渠道重要性为 DEFAULT。简中、英文、繁体各看一遍新文案；深浅色各看一遍。
12. 两端单测全绿；iOS 在 `iPhone 17e`、安卓在模拟器亲验 1、3–9 条并截图对照屏幕稿；第 2 条 iOS 真机由 Opus 陪 David 验。

## 测试 seam

- **完成闸门**：抽纯函数（如 `completionGate(videos) -> .completeNow | .waitForDelivery(done,total)`）+ 一个「等待送达后自动完成」的协调器（需持久化，杀进程后恢复），在 iOS StudentKit / RN `video-upload` 的 manager 层测：注入上传状态流与时钟，断言长按后奖励页数据立即可得、完成接口只在全部送达后调用一次、30 分钟发一次超时通知。复用 069 `UploadRetryScheduler` / RN `retry-scheduler.ts` 的时钟注入。
- **零丢失**：iOS `RetainedVideoCleanupPolicy`、RN `localRetentionRemovals` 的决策表测试（已有 seam，补用例）。
- **失败态展示**：iOS `CompletedDayPresentation` / 今日卡展示模型、RN `completed-replay.ts` 的纯函数，断言失败组输出失败标记。
- 通知授权与渠道：只测调用参数（provisional 不再出现、渠道 importance），不写系统集成测试。

## Out of Scope

- 视频挂错组的竞态根因修复（另走 P0 修复卡）。
- 教练端任何「学员有视频没传上」的提示（iOS 教练模式、plan-web）。
- 后端改动、服务端孤儿视频的找回与回填（由 P0 修复卡的存量方案负责）。
- 在传过程中的进度条、百分比等常驻 UI（保持 069 无感口径，只在完成前统一显示）。
- 引导安卓学员开启后台高耗电 / 自启动权限。
- 修改分片大小、退避序列、上传协议。
