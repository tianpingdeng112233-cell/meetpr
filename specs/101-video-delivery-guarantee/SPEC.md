# 101 — 训练视频零丢失：送达后才完成 + 失败提醒

- **状态**: Ready（2026-11-05 /grill 共识「确认」；屏幕稿待「定稿」）
- **来源**: 学员反馈「有些视频被吞了」（2026-11-05 iOS 真机录屏：W1D5、W2D1 卧推第 1 组、W2D2 深蹲第 3 组回看无视频）。
- **范围**: 学员端，iOS（`MeetPR` 仓 `release/1.0`）与安卓 RN（`meetpr-rn` 仓 `main`）同批派卡、同批验收；两仓同目录镜像本文件。
- **级别 / 节奏**: T2 / P1。纯客户端，无后端、无数据模型改动（若实装中发现必须改后端，停下回报，不自行扩范围）。
- **前置**: 视频挂错组的竞态 P0（`docs/diagnose/set-video-lost-2026-11-05.md`，iOS 已在本地复现）**另走修复卡**，不在本 spec 内；本 spec 是在它之上加的保障与提醒，两者可并行。

## 北极星（David 原话口径）

**视频千万不能丢——学员不可能重新练一组。** 任何状态、任何清理、任何失败路径都不允许出现「请重新录」。

## 术语

**视频送达**：某组的视频在服务端上传完成，并且已挂到这一组上。只有送达才算这条视频的事结束了。在此之前它只是「在传」或「没传上」。

## 现状（已核实，iOS `origin/release/1.0` 09eef51d / RN `origin/main` 6550369）

- 两端已有分片上传 + 断点续传 + 指数退避重试（iOS spec 069：background `URLSession`，每片 etag 落盘；RN `multipart.ts` / `retry-scheduler.ts`）。退避约 1/2/5/10/15 分钟，30 分钟时间盒。
- 失败通知：iOS `UploadFailureNotifier` 用 **provisional（静默进通知中心）** 授权、30 分钟后才发；RN `failure-notifier.ts` 用 `video-upload` 渠道、`AndroidImportance.LOW`。
- 失败态 UI：只在记录弹窗的视频附件区显示「上传失败 + 重试」。**已完成训练日回看（spec 096）与今日训练卡没有失败态**——传失败的组只是少一个播放图标。
- 「完成今日训练」不看视频状态，有视频没传完也能完成。
- 本机留存（spec 070）：iOS `RetainedVideoCleanupPolicy` 只清「已上传」的文件，没传上的不碰 ✅。**RN `localRetentionRemovals` 的 500MB 护栏会删除「已准备、未上传」的文件** ❌——违反北极星，本 spec 修。
- 相机直拍：iOS `CameraRecorderView` 在学员授权相册时另存一份到相册；RN 待实装方核实并写进 JOURNAL。

## 变更

### 1. 零丢失（两端）
1. 一条视频在**送达**之前，本机文件不得被任何清理删除（隔天清扫、500MB 护栏、冷启动、换包升级都算）。超过 500MB 时只清已送达的；全是未送达的就不清，宁可超限。
2. 没有「视频已丢失 / 请重新录」状态。所有失败都可重试。
3. 极端情况本机文件确实不在了（卸载重装、系统清理）：该组显示失败态，重试动作变为「从相册重新选这条视频」，选好后挂回原来那一组，走正常上传。

### 2. 完成今日训练前统一检查（两端）
点「完成今日训练」时，若当天有任何一组视频**未送达**（在传、退避中、失败都算）：
1. 不立即完成。显示「视频上传中 2/3」类进度（N = 当天未送达 + 已送达总数），并立即重试所有失败/退避中的视频（插队，不等退避）。
2. 学员可以离开这个页面或离开 app，不需要守着。
3. 全部送达后**自动完成当日训练**（走现有完成接口，语义不变），并发通知「今日训练已完成，N 条视频已送达」。学员若此时在 app 里，页面直接切到已完成态，通知照发与否以屏幕稿为准。
4. 自点击起 **30 分钟**仍未全部送达：发通知「还有 N 条视频没传上，点击重试」；点通知 → 进 app 定位到今日训练，再次全部重试。今日训练保持「等视频送达后完成」的状态，不回退成未完成。
5. 当天没有视频或全部已送达：行为与现在完全一样，立即完成。
6. 「撤销完成」现有行为不变。

**安卓差异（David 拍板 A）**：vivo 等机型会冻结后台进程并删定时器，且不引导学员开高耗电权限。安卓在后台能传就传；传不完则在学员下次打开 app 时自动接着传、传完自动完成；第 3、4 条的通知「尽量发」——后台被冻结时发不出不算缺陷。iOS 必须按上面完整做（background session 唤醒后发完成接口 + 本地通知）。

### 3. 失败态可见（两端）
「失败」= 某组视频上传第一次失败（含正在退避重试）。页面上**第一次失败就显示**，不等 30 分钟；后台照常自动重试，送达后失败态自动消失。
1. **今日训练卡**：失败组的行尾显示失败标记；卡片内有一条「N 条视频没传上 · 重试」，点它全部重试。
2. **已完成训练日回看（096）**：同上——失败组行尾显示失败标记（替代播放图标的位置），动作卡或日卡上有「重试」入口。主要覆盖本 spec 上线前就已经完成、视频没送达的历史训练日。
3. 正在正常上传、还没失败的视频：页面上不单独提醒（保持 069「无感」口径），只在第 2 节「完成今日训练」时统一体现。
4. 具体图标、颜色、文案位置以「定稿」屏幕稿为准。

### 4. 通知（两端）
1. iOS：视频上传相关通知从 provisional 改为正常横幅提醒，复用推送已有的通知授权；没有授权时请求一次正常授权；被拒则只靠页面失败态。
2. 安卓：`video-upload` 渠道重要性从 LOW 提到 DEFAULT（有横幅/声音按系统默认）。
3. 原 069 的「网络失败 30 分钟后冒头 / 确定性失败立即冒头」规则保留，文案统一为「有 N 条训练视频没传上，点击重试」。同一时刻只保留一条聚合通知，不逐条轰炸。

## 文案（简中 / English；繁体走现有生成流程）

| 用途 | 简中 | English |
|---|---|---|
| 完成前进度 | 视频上传中 {done}/{total} | Uploading videos {done}/{total} |
| 完成前进度副文案 | 传完会自动完成，可以先离开 | We'll finish your workout once they're up. You can leave now. |
| 自动完成通知 | 今日训练已完成，{n} 条视频已送达 | Workout complete. {n} videos delivered. |
| 超时 / 失败通知 | 还有 {n} 条视频没传上，点击重试 | {n} videos didn't upload. Tap to retry. |
| 卡片失败条 | {n} 条视频没传上 · 重试 | {n} videos didn't upload · Retry |
| 本机文件不在时的重试 | 从相册重新选这条视频 | Pick this video again from Photos |

（英文单复数按现有 i18n 规则；最终措辞以屏幕稿定稿为准。）

## 验收清单

1. 两端：当天 3 组带视频，断网后点「完成今日训练」→ 显示「视频上传中 0/3」，今日训练**不**进入已完成；恢复网络后自动送达并自动完成；iOS 收到完成通知。
2. iOS：点完成后立即杀 app，网络正常 → 视频在后台送达、当日训练自动完成、收到完成通知（真机 HITL，模拟器只验前台路径）。安卓：点完成后杀 app → 下次打开自动接着传并完成。
3. 两端：点完成后保持断网 30 分钟（测试用可注入时钟）→ 收到「还有 N 条视频没传上，点击重试」；点通知进今日训练并触发重试；今日训练仍是「等送达」状态。
4. 两端：某组视频上传第一次失败 → 今日训练卡立即出现失败标记与「N 条视频没传上 · 重试」；恢复网络后自动送达，失败标记消失。
5. 两端：已完成训练日里有未送达的视频 → 回看页该组显示失败标记与重试入口；重试送达后变回播放图标。
6. 两端：当天无视频或全部已送达 → 点完成立即完成，与现在完全一致。
7. 两端：留存清扫决策表——未送达文件在隔天、超 500MB、冷启动三种情况下都不被删除；RN 现有「已准备未上传被护栏删除」用例改为先红后绿。
8. 两端：本机文件被删后（测试里直接删文件）该组显示失败态，重试变为「从相册重新选」，选好后挂回原组并送达。
9. **带历史的老用户升级后第一屏**：升级前已有「在传 / 失败」视频的老数据，升级后不丢、按新口径显示失败态并可重试；已送达的视频与回看不受影响。
10. 两端：iOS 通知为正常横幅（非静默）；安卓渠道重要性为 DEFAULT。简中、英文、繁体各看一遍新文案；深浅色各看一遍。
11. 两端单测全绿；iOS 在 `iPhone 17e`、安卓在模拟器亲验 1、3–8 条并截图；第 2 条 iOS 真机由 Opus 陪 David 验。

## 测试 seam

- **完成闸门**：抽纯函数（如 `completionGate(videos) -> .completeNow | .waitForDelivery(done,total)`）+ 一个「等待送达后自动完成」的协调器，在 iOS StudentKit / RN `video-upload` 的 manager 层测：注入上传状态流与时钟，断言只在全部送达后调用一次完成接口、30 分钟发一次超时通知。复用 069 `UploadRetryScheduler` / RN `retry-scheduler.ts` 的时钟注入。
- **零丢失**：iOS `RetainedVideoCleanupPolicy`、RN `localRetentionRemovals` 的决策表测试（已有 seam，补用例）。
- **失败态展示**：iOS `CompletedDayPresentation` / 今日卡展示模型、RN `completed-replay.ts` 的纯函数，断言失败组输出失败标记。
- 通知授权与渠道：只测调用参数（provisional 不再出现、渠道 importance），不写系统集成测试。

## Out of Scope

- 视频挂错组的竞态根因修复（另走 P0 修复卡）。
- 教练端任何「学员有视频没传上」的提示（iOS 教练模式、plan-web）。
- 后端改动、服务端孤儿视频的找回与回填（由 P0 修复卡的存量方案负责）。
- 在传过程中的进度条、百分比等常驻 UI（保持 069 无感口径，只在完成前统一显示）。
- 引导安卓学员开启后台高耗电 / 自启动权限。
- 修改分片大小、退避序列、上传协议。
