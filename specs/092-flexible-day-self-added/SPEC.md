## 术语(已写入仓根 `CONTEXT.md`)

- **游标日**:计划里按顺序最早一个还没结算的训练日。
- **额外组**:教练排的某个动作下,学员在处方组之外多做的组。
- **自加动作**:学员在某个训练日里自己从动作库加练的、计划里没有的动作;只属于那一次训练。
- 额外组与自加动作合称**学员自加记录**。

## 已拍板口径

| 题 | 结论 |
|---|---|
| 1 跳着练之后 | 被跳过的天保持待练;下次打开仍默认指向游标日,学员可再换。不改教练的计划 |
| 2 可以换多远 | 只能在本周内换;下一周照旧只读预览 |
| 3 自加动作归哪 | 只属于这一次训练,不改计划,下周同一天不会再出现 |
| 4 加组范围 | 教练排的任何动作末尾都能加额外组(主项也行),处方原样不动 |
| 5 教练可见 | 教练 app 与教练网页都显示,带「学员自加」标记;跳练按实际完成情况显示;不发通知 |
| 6 本周剩一天不想练 | 维持现状:本周没结算完进不了下一周,要么练(至少 1 组后结算),要么找教练改计划 |
| 7 练到一半换天 | 允许;两天的记录各自保留、各自结算 |
| 8 自加动作来源 | 只能从动作库搜索选择,不能手打库外名字 |
| 9 视频 | 额外组可以拍(与同动作其他组同一条链路);自加动作本期不能拍 |

## §1 本周内换天练

**本周** = 游标日所在的计划周(`week_number`)。

- 本周内**任何没结算的训练日**都可以开始、记录、结算,与今天的游标日完全同等(完整录入、辅助项记录卡、休息计时、视频、结算庆祝全部照常)。今天只有游标日可写,其余「之后的天」是只读预览——本条把本周内的这部分从只读改为可写。
- 其他周的训练日维持现状:之前的周只读详情,之后的周只读预览。已结算的天维持现状(只读详情 + 撤销规则不变)。
- **周历外观与交互一律不改**(David 2026-10-13 看稿后明确:「训练页日历还是和之前一样,只是可以自由切换并开始训练」):页头、周次行、七天周历、「回到今天」、训练日卡的结构全部沿用现状。唯一变化在训练日卡——选中本周内另一个未结算日时,原来的「完成 X 后解锁」说明换成「开始训练」主按钮,点了进入与游标日相同的记录态。
- 周条(spec 084b / 086)上本周的未结算日都可点选并进入记录态;被跳过的天与还没轮到的天外观一致(都是待练),不新增「已跳过」状态。已结算的天照常显示完成,即使它排在未结算的天后面。
- **默认选中**:打开训练页时默认选游标日。例外——当天(gym-day)已经在某个未结算的天记录过至少一组时,默认回到那一天(否则练到一半杀进程再进来会跳回另一天)。同时有多个这样的天时取最后记录的那一个。
- **练到一半换天**:从 D2(已记 2 组、未结算)切到 D4 时不提示、不清空;D2 的记录原样保留,回到 D2 继续记、照常结算。两天可以在同一个 gym-day 里各自结算。休息计时在换天时结束(现状)。
- **结算与撤销**:结算靠后的天不影响靠前的天;结算后默认选中回到游标日。撤销规则不变(只能撤销当天最新结算的那一条)。
- **Today 页**:主卡与「开始训练」仍指向游标日(现状);在 Today 的周历上点本周另一个未结算日再进入训练页,按上面的规则可直接开始。
- 写入门:现有「所选日已不是当前训练日」的保存拦截改为「所选日已不可写」——计划不再是已发布、或所选日已结算、或所选日不在本周时才拦,文案沿用。
- 「落后 N 天」、推荐日期、训练提醒的口径全部不变(仍看游标日)。

## §2 额外组

- **入口**:可写的训练日里,每个动作的组列表末尾有一个「加一组」(英文 `Add set`)。主项 / 主项变式(完整录入)与辅助项(记录卡行内表格,spec 089)都有。只读的天不出现。
- **新加的一行**:标「额外」(英文 `Extra`);重量与次数预填这个动作本次训练里最后一条已记录的组,没有则用最后一个处方组的数值(纯 RPE 处方时重量留空,占位规则与现状一致);没有处方目标,RPE 选填。
- **记录**:与处方组走同一条路径、写同一种记录(挂在该计划动作上,组序号接在最后)。PR 判定、e1RM、历史照常。可以拍视频、从相册选、标记失败。
- **休息计时**:按这个动作现有的规则(主项按 RPE 分档 / 学员设置;辅助项用辅助项时长);教练给处方组设的休息时间不套用到额外组。
- **进度**:额外组不计入「第几组 / 共几组」、组进度条与「还差几组」;做了额外组不能顶替没做的处方组。结算入口的出现条件不变(已有 ≥1 组真实记录)。
- **删除**:还没记录的额外组行可直接移除;已记录的可删除(确认一次),带视频的要先到完整录入页处理视频;教练已经给这一组填过教练 RPE 的不能删,提示「教练已评过这一组,不能删除」(后端 spec 050 的 `SET_HAS_COACH_FEEDBACK`)。处方组不能删。
- 每个动作最多 10 个额外组。
- 已结算的天的只读详情里,额外组照常列出并带「额外」标记。

## §3 自加动作

- **入口**:可写的训练日里,动作列表最下方有「加动作」(英文 `Add exercise`)。只读的天不出现。
- **选择**:打开动作库选择页——搜索框 + 一行筛选标签 + 列表,只列动作库里的动作(名称跟随界面语言),不能手打新名字。
  - 筛选标签(David 2026-10-13 / 10-14 三轮看稿后定):叫法与教练网页动作库一致;**三行、全部一屏可见、不横滑**,三行合起来单选,与搜索词同时生效,默认「全部」,标签不带数量,不做器械筛选。第一行:全部｜深蹲族｜卧推族｜硬拉族｜核心｜其他(三个「族」列该族的主项与主项变式,按动作库的 `main_lift_family`)。第二行上肢:胸｜背｜肩｜二头｜三头｜斜方肌｜前臂。第三行下肢:股四头｜臀｜腘绳肌｜小腿｜内收肌｜髋。为了一屏放下,把网页里动作很少的几类并入相邻标签(Opus 提的并法,待 David 确认):握力→前臂,髋屈肌→髋,胫骨前肌→小腿,灵活性与心肺→其他。按动作库的 `muscle_groups` 归类,一个动作可出现在多个标签下;没有肌群信息的动作只在「全部」里。页面底部不放说明文字(David 在画布上删掉了)。
  - 这一天的计划里已有的动作:列表里置灰并注明「已在今天的计划里,可在该动作下加一组」。
  - 这一天已经自加过的动作:置灰。
- **卡片**:选中后在这一天的计划动作之后追加一张自加动作卡,标「自加」(英文 `Added by you`)。卡内是行内表格(组号｜上次｜重量｜次数｜RPE｜✓,与辅助项记录卡同一套行为:点 ✓ 记录、再点取消、「上次」取这个动作上一次的记录),初始一行,末尾「加一组」。不分主项辅助项都用这张卡;没有处方、没有教练备注、没有「全部按计划完成」、组号不可点进完整录入(本期不拍视频)。
- **记录**:写成挂在这个训练日上的计划外记录。PR 判定、e1RM(属于深蹲 / 卧推 / 硬拉家族时)、历史照常。
- **休息计时**:点 ✓ 后起计时;动作库类型是辅助项的用辅助项时长,其余按学员现有的休息设置。
- **进度**:不计入当天进度与「还差几组」,不挡结算;只做了自加动作、处方一组没做时,结算入口的出现条件按现状(已有 ≥1 组真实记录——自加动作的记录算真实记录)。
- **移除**:可以移除整张卡(确认一次,连同它已记录的组);单行的删除同额外组。
- 每个训练日最多 10 个自加动作,每个最多 10 组。
- 已结算的天的只读详情里,自加动作列在计划动作之后并带「自加」标记。训练历史页同样显示。
- 同一天(gym-day)同一个动作只能自加在一个训练日里;在另一个训练日再加同一个动作时提示「今天已在另一个训练日加过这个动作」。

## §3b 点 ✓ 的震动反馈

David 2026-10-14 定稿时追加:学员点行内表格的 ✓ **把一组记为完成**时,手机给一次短震动。

- 范围:所有行内表格的 ✓——辅助项记录卡的处方组(spec 089)、额外组行、自加动作卡的行。
- 时机:按下的当下就震(不等保存返回),一次、约 15 毫秒,用仓内现有的震动机制(`FeedbackPressable` 的 `haptic` / `Vibration`),不加依赖、不加权限。
- 不震的情况:再点一次取消这组;✓ 置灰不可点;写入进行中的重复点击;「全部按计划完成」(它是主按钮,沿用按钮现有的反馈)。
- 保存失败时沿用现有失败提示,不补第二次震动。
- 主项完整录入页的「完成这组」按钮维持现状(已有按钮反馈),本条不改。

- 导出 CSV:额外组与自加动作照常导出(自加动作 `adhoc` 列为 true,现状)。
- 离线演示模式(PR #88)尚未合入 main,本 spec 不覆盖;它合入时再补。

## §5 教练 app(本仓 `(coach)`)

- 学员详情 → 训练日详情:
  - 计划动作下的组列表里,额外组排在处方组之后;处方组与额外组之间插一行小灰字「学员自加」(英文 `Added by student`),额外组的行本身与其他行同样式、行上不加标签(David 2026-10-14 看稿后定:「不要加到行上,一行小字即可」)。「已记录 x / y 组」的 x 只数处方内的组。
  - 计划动作之后单列该训练日的自加动作,每个动作一张卡;标题不带标签,副标题一行小灰字「学员自加 · 不在计划里 · 记录了 N 组」,组以同样的只读行显示。
- 读取自加动作需要带新的读取范围(后端 spec 050 §3)。
- 跳练:周 / 日列表上各训练日按各自的完成状态显示(靠后的天已完成、靠前的天未完成是正常状态),不加额外标记、不发通知。凡是假设「游标之前的天都已完成」的教练侧展示逻辑,逐个核对并修正。
- 待看视频、聊天里的组卡片:额外组的视频与处方组一样进入现有流程,不加标记以外的差异。

## §6 教练网页(`meetpr-plan-web`,另立 spec)

- 沿用网页现有的实际记录显示(David 2026-10-14 贴了现状截图):每个动作行的强度格、重量格下方各有一行「实际」加小圆角标签(如 `115×8`)。额外组接在处方组的标签之后,中间插一个小灰字「学员自加」,额外组的标签用中性灰底(不参与「与处方偏差」的红黄配色,因为没有处方可比)。
- 自加动作在该训练日的计划动作行之后以只读行显示:动作名下一行小灰字「学员自加」(David 在画布上把「· 不在计划里」删掉了),组 / 次 / 强度格显示 `–`,重量格照常是「实际」加中性灰标签。只读,不可编辑、不可拖动,不进计划树,不参与发布门禁、复制周、后移,也不计入该日「N 组 · 总量」的处方统计。
- 右侧上下文栏里显示实际记录的地方同样要能看到这两类。
- 统计 / 视频页里按计划动作归集的视图不因额外组错位。

## 存量数据与升级

- 不迁移任何本地存储;进行到一半的训练日升级后照常继续。
- **带历史的老用户升级后的第一屏**:训练页默认选中与升级前一致(游标日;当天已在游标日记过组的仍是游标日);周条上本周其余未结算日从「只读预览」变为可点进记录态,这是唯一的可见变化。
- 后端迁移纯增量,存量行不受影响(见后端 spec)。
- 版本交错:安卓新包写出的额外组,老版本客户端(iOS 1.0(23) 及以前、未升级的安卓包)读到的是该动作下多出来的记录行;验收时确认老包看这样的训练日不崩、不串组。自加动作行老包读不到(它们不请求这类记录)。

## 验收清单

学员端(安卓模拟器,中英文各一遍,含深色与小屏大字号各抽一屏):

1. 本周游标日是 D2:周条上点 D4 → 进入记录态,记一组成功;回到 D2,其记录与 D4 互不影响。
2. D2 记 2 组后切到 D4 记满并结算 → D4 显示完成,D2 仍待练且 2 组还在;默认选中回到 D2。当天再结算 D2 成功;撤销只能撤最后结算的那一个。
3. 下一周的训练日仍是只读预览、无「加一组 / 加动作」入口;上一周已结算的天仍是只读详情。
4. 当天在 D4 记过组、未结算,杀进程重进 → 默认停在 D4;第二天(过 04:00)重进 → 默认回到游标日。
5. 主项动作「加一组」:新行带「额外」,预填上一组数值;记录后进度条与「第几组 / 共几组」不变;可拍视频并出现在教练待看;可删除(带视频的被拦并提示)。
6. 辅助项记录卡「加一组」:行内新增一行,✓ / 取消 / 删除可用;「全部按计划完成」不包含额外组。
7. 处方 3 组只做 2 组 + 1 个额外组 → 该动作仍显示还差 1 组。
8. 「加动作」:搜索可用;计划里已有的动作置灰带提示;选中后出现自加动作卡,记录 / 取消 / 加组 / 删行 / 移除整卡可用;记录后历史页与进步页(若属三大项家族)可见。
9. 自加动作与额外组的上限(10)到达后入口置灰。
9b. 点 ✓ 完成一组有一次短震动;取消、置灰、「全部按计划完成」不震(真机验,模拟器只验调用)。
10. 带历史的老用户升级第一屏符合「存量数据与升级」。
11. 断网时记录额外组 / 自加动作:沿用现有保存失败提示,不丢已填数值,恢复后可重试成功。

教练端:

12. 教练 app 训练日详情:额外组与自加动作可见且带「学员自加」;「已记录 x / y」不被额外组撑大;学员删除后教练端刷新即消失。
13. 教练 app:学员先结算 D4 后,D2 未完成、D4 已完成的显示正确,无报错。
14. 教练网页:§6 两条。
15. iOS 1.0(23) 学员 / 教练 demo 打开一个含额外组的训练日不崩、不串组。

后端验收清单见后端 spec 050。

3. **草稿与行模型**(`src/features/training/` 下 drafts / accessory 行模型的纯函数测试,现有 seam):处方组 + 已有额外组记录合并成行、进度只数处方组、额外组预填、自加动作行模型、上限。
4. **请求体构造**(现有 `accessory-quick-log` / set-save 的纯函数测试 seam):额外组的 coached 请求、自加动作的计划外请求(带训练日)、删除。
5. **教练训练日详情的归集**(`src/domain/coach/` 现有纯函数测试 seam):额外组排序与标记、自加动作分组、x / y 计数。
6. **屏幕级**:训练页现有的屏幕测试里加一条「本周换天 → 记录 → 结算」主路径;不为每个入口各写一条。

## Out of Scope

- 跳过整天、「本周剩下的不练了」、跨周换天。
- 删 / 换 / 改教练排的动作与处方组;把自加动作写进计划。
- 手打库外动作名、自定义动作。
- 自加动作的视频;给教练的通知 / 推送。
- 补记里加额外组或自加动作;给已结算的天直接加(先撤销结算)。
- iOS 原生实装(安卓收货后另立)。
- 自己练(无教练)形态的任何改动。
