# Spec 109 · 辅助项上次重量

Status: Done · T2 / P1 · 2026-11-13 David 定稿并授权进下一班 iOS / Android。

先读仓根 CONTEXT.md、AGENTS.md / CLAUDE.md。正典为 iOS 仓本 spec；Android 同目录是本次批准内容的交付快照。本 spec 只解除 spec 107 的辅助项历史重量暂缓，主项及变式仍暂缓。

## 批准行为与范围

1. 动作库类型 accessory 才启用。默认全天一览紧凑行，点开才是现有编辑态；不恢复旧六列表格、不加“上次”列。
2. 同一动作最近一次实际训练，跨计划与训练日，按 set index 对应；只用完成、非失败、非推定的真实组。先选最近一次 session，再找组；组不存在或重量为 null 就留空，不向更老 session 补组，不借最后一组。
3. 已保存值（含明确保存的 null）、本地手动编辑、教练明确重量优先；否则辅助项无具体重量时沿用历史。旧自重、百分比、重量区间口径保持；不替换器械或动作 ID，不改次数、RPE/RIR。
4. 历史预填重量在紧凑行呈金色。编辑时仅历史预填的重量数字右侧出现金色小字“上次”，不重复历史重量、不换行到下方。手动改重量后取消历史预填金色和“上次”标记；教练明确值和已保存值不是预填。只是打开/收起不清除来源，不创建记录。
5. 手动改一组不联动其余组；缺对应历史的新增组留空。历史请求迟到/刷新不得覆盖已编辑值；失败不阻断训练。身份/选日切换不能泄漏其他用户/日期数据。
6. 完成、可空重量、离线队列、逐次编辑保存、视频、动作勾选、训练日结算沿用 spec 107；预填本身不发写入。原型只批准布局和历史来源交互，不替换现有保存及完成契约。

## 实装卡（每仓一张）

- iOS：已有日志历史 → 最近 session 组映射 → TodayWorkoutViewModel 草稿 → AllDaySetRow 紧凑值与重量格。
- Android：已有 useSetLogs 历史 → all-day-sheet 草稿投影 → AllDayBody 紧凑值与重量格。
- 复用当前模型、缓存、数字键盘与国际化。可选草稿元数据兼容旧缓存缺字段，服务端请求不新增字段。

## 测试 seam

沿用既有公开 seam：iOS TodayWorkoutViewModel.load/updateWeight、AllDaySetRow / WorkoutKeypadSession；Android buildAllDaySheet、TodayWorkoutView / AllDayBody 用户操作。历史选择作为纯函数 seam；通过已知日期/重量 fixture 验证最近一次与缺组语义。每个行为先红后绿。
